## 의도

- **출처**: 의도 문서 `%APPDATA%\orca\floating-workspace\aitray.md`(2026-10-11 판) +
  [부트스트랩 인터뷰](overview/bootstrap-interview.md).
- **목표**: 해당 프로세스를 실행하고 있는 PC 간 Claude 간 통신할 수 있는 툴 개발.
- **문제**: 같은 claude.ai 계정의 내 세션끼리는 Claude Code 기본 기능(`SendMessage` + Remote Control, Anthropic
  서버 경유)으로 PC 를 넘지만, **다른 사용자(계정)의 Claude 에이전트와 대화할 경로는 없다** — 공식 문서에 계정 간 ·
  LAN 직접 경로가 없다(2026-10-11 조사).
- **비목표**: 파일 전송(텍스트·마크다운만) · 인터넷 너머 연결(허브 경유 포함) · 3 PC 이상 다자 채널 · Linux ·
  Windows ARM64 · 모바일 · 메시지 수정/삭제 동기화 — 인터뷰 Q2 · Q6 · Q7 · Q22. "1:1 대화만" 은 Q17 답에서 철회됐다(D23).
- **성공 기준**:
  - SC1: 서로 다른 사용자의 PC 2대(Windows · macOS 각 1대 이상)가 같은 LAN 에서 중앙 서버 없이 페어링하고, 한쪽 사람이
    쓴 메시지에 상대 PC 의 등록 에이전트가 `claude -p` 로 답한다.
  - SC2: 페어링하지 않은 PC 의 메시지는 처리되지 않고, 에이전트에 허용하지 않은 도구는 원격 메시지로 실행되지 않는다.
  - SC3: 대화의 요청/응답 전체가 양쪽 SQLite 에 남고 채팅 모양으로 보이며, 나중에 같은 대화에 이어 쓰면 에이전트가 이전
    맥락으로 답한다.
  - SC4: 두 에이전트의 자동 왕복이 상한에서 멈춘다.
  - SC5: 배포물은 OS 별 실행 파일 1개 — 설치 없이 실행해 트레이 상주 · 자동 실행 · 서명 검증된 자동 업데이트 ·
    `coworkAgent chat` 진입이 동작한다.

## 확정 방향

D1~D5 는 의도 문서 "방법" 을 그대로 옮겼다(기각안·이유는 문서에 있는 것만). D6~ 는 부트스트랩 인터뷰.

- **D1** 구현 언어는 Rust — 이유: Windows·macOS 모두 지원 필요. 기각안: 미기재.
- **D2** 단일 실행 파일로 구현.
- **D3** 서버/클라이언트 구현을 나누지 않고 단일 실행 파일이 서버/클라이언트를 모두 제공.
- **D4** 모든 UI 는 웹UI 로 구성. 표시 방식은 D9.
- **D5** 개발 flow 는 `sc-workflow-ddd`(DDD) — 본 문서 체계.
- **D6** (Q1) 용도는 다른 사용자·PC 간 **에이전트 대화** — 사용자 답 원문 "다른 사용자 및 PC 간 에이젼트 대화
  용도임." 기각안: 사람↔사람 메신저 · 혼합(주소 = 사용자). 이유: 같은 계정의 세션끼리는 기본 기능이 이미 PC 를
  넘는다(`## 의도` 문제). 사람의 역할은 D18.
- **D7** (Q2) 피어 발견은 같은 LAN 자동 발견(mDNS) + 수동 주소(IP:포트) 추가. 중앙 서버 없음 — 오프라인 상대에게
  보낸 메시지는 발신 PC 가 보관했다가 상대가 다시 보이면 재전송. 기각안: 허브 경유 · 인터넷 너머. 이유: 사내망은
  VLAN 간 멀티캐스트 차단이 흔해 수동 추가가 안전판.
- **D8** (Q3) 신원·보안: 설치별 ed25519 키쌍 신원 + 최초 연결 시 양측 승인(지문 비교 페어링) + 전 구간 공개키 고정
  TLS. 원격 메시지는 신뢰하지 않는 입력(루트 `PROJECT.md` 가드레일). 기각안: 팀 공유 키 · LAN 신뢰 무인증.
- **D9** (Q4) 웹UI 는 내장 웹서버(127.0.0.1 전용) + 기본 브라우저 탭, 실행마다 바뀌는 토큰 + Host/Origin 검사로
  보호. 기각안: 앱 창(WebView). 이유: 단일 실행 파일 최단 경로, OS 웹뷰 의존 없음.
- **D10** (Q5) 프론트엔드는 빌드 없는 정적 HTML/CSS/JS(ES modules)를 실행 파일에 임베드. 기각안: React/Svelte + Vite.
  이유: `cargo build` 하나로 산출.
- **D11** (Q7) 대상은 Windows 10/11 x64 · macOS 12+ universal(arm64+x64) 단일 파일. 제외: Windows ARM64 · Linux.
  mac 빌드는 보유한 Mac 에서(사용자 답 원문 "보유한 mac 에서 빌드.").
- **D12** (Q8) 자동 업데이트 배포처는 Phase 4 직전에 결정. 형식: HTTPS 매니페스트 + 업데이트 파일 서명 검증(앱 자체
  ed25519) + 실행 파일 교체. 코드 서명 인증서(Authenticode · Developer ID)는 개발 완료 후 검토 — 사용자 답 원문
  "개발 완료 후 서명 추가 검토." 업데이트 파일 서명 검증을 S6 에 포함하는 것은 2라운드 Q8 확인 무응답 → 권장 수용(잠정).
- **D13** (Q9) 자동 실행은 첫 실행 시 기본 ON + 트레이 메뉴 체크 토글(Windows `HKCU\…\Run` · macOS LaunchAgent,
  사용자 권한). 기각안: 기본 OFF. 이유: 꺼져 있으면 상대 목록에서 사라진다.
  자동 실행에는 **"시작 시 웹UI 열기" 옵션**을 함께 둔다 — 브라우저 알림(D29)은 웹UI 탭이 열려 있어야 뜨므로 그 공백을 줄인다.
  사용자 답 원문 "권장안 승인"(2026-10-11). 기본값은 S7 Task 착수 때 확인.
- **D14** (Q10) 실행 파라미터 literal(2026-10-11 제품 이름 변경 — 구 `agentNetwork`): `coworkAgent`(트레이 상주) · `coworkAgent chat [--peer <사용자ID>]`(대화 UI 로
  바로 진입). 단일 인스턴스 — 이미 실행 중이면 새 프로세스는 기존 인스턴스에 요청을 넘기고 종료. 기각안: 플래그형

- **D15** (Q11) 저장 경로(2026-10-11 제품 이름 변경 — 구 `agentNetwork`): Windows `%LOCALAPPDATA%\coworkAgent\` · macOS `~/Library/Application Support/coworkAgent/`.
  기각안: `%APPDATA%`(Roaming). 이유: 로밍 프로필 복사 → 신원 키 중복(ID 충돌) · SQLite 손상 위험.
- **D16** (Q15) Claude 연동은 **`claude -p` 헤드리스 실행** — 메시지를 받은 PC 의 coworkAgent 가 그 PC 의 Claude Code 를
  `-p` 로 실행해 답을 만든다. 사용자 답 원문 "claude -p 의 해드리스 명령어로 연동." 기각안: MCP stdio(pull — 수신 측
  사람이 세션에 대기를 시켜야 함) · Channels 푸시(preview · 대화형 세션 전용 · 조직 설정 필요) · 훅. 성질: 수신 측에
  띄워 둔 세션이 필요 없다. 전제: 각 PC 에 Claude Code 설치·로그인 — 계정은 D20.
- **D17** (Q16) 원격 메시지는 **자동으로 처리**한다(전달·응답에 사람 승인 게이트 없음) — 사용자 답 원문 "자동으로 동작."
  도구 실행 권한은 D22.
- **D18** (Q17) 사람은 대화에 **직접 작성**한다(발신자 '사람' 표시) — 사용자 답 원문 "b 사람은 직접 대화를 작성.
  Q6답변 번복." 이에 따라 Q6 의 "1:1 대화만" 비목표를 철회했다. 대화 구성은 D23.
- **D19** (Q18) 이력은 **요청/응답 전체**를 남기고 채팅 이력 모양으로 보여 주며, 나중에 그 이력에 **이어서 작업**할 수
  있다 — 사용자 답 원문 "요청/응답에 대한 전체 이력. 해당 이력은 채팅 이력 모양으로 보여주며, 나중에 해당 이력에 이어서
  작업 가능해야해함." 이어서 작업 = 대화마다 에이전트의 Claude 세션 ID 를 저장해 다음 실행을 그 세션의 resume 으로
  잇는다(`--resume` · `--session-id` — 검증 환경 Claude Code 2.1.296 `--help`). 같은 세션의 동시 재개는 잠금 없이 섞이므로
  대화별로 직렬 실행하고, 재개 시 작업 폴더는 문서에 없으므로 에이전트별 폴더를 고정한다(공식 문서).
- **D20** (Q24) Claude 계정은 **각 PC 의 Claude Max 구독 로그인** — 사용자 답 원문 "claude max 구독이 설정되어있는 pc 에
  해당 프로젝트의 바이너리를 배포할 거야." 기각안: 회사 Console API key · Team/Enterprise 플랜. 정책 원문(Free·Pro·Max
  자격으로 타인 요청 중개 금지 · Max 사용 한도는 개인 사용 전제 — [인터뷰 문서](overview/bootstrap-interview.md) 조사한
  사실)을 고지한 뒤의 사용자 결정이며, Anthropic 확인은 하지 않았다. 귀결: 구독 OAuth 를 읽지 않는 `--bare` 를 쓰지
  않는다(문서상 향후 `-p` 기본값 예정 → Claude Code 업데이트마다 회귀 확인) · 원격 요청이 수신 측 Max 사용량을 쓴다.

D21~D24 는 3라운드 무응답 뒤 사용자의 "공유 이해" 확인으로 권장안을 수용한 것이다.

- **D21** (Q20) 에이전트 = 수신 PC 사용자가 웹UI 에서 등록한 **프로필**(이름 · 작업 폴더 · 허용 도구 · 추가 지시문). 원격은
  `사용자/에이전트명` 으로 등록된 것만 부른다. 기각안: PC 당 기본 에이전트 1개 · 원격이 작업 폴더 지정. 이유: `-p` 의 실행
  폴더가 곧 맥락이자 원격으로 나갈 수 있는 범위다 — 그 PC 사람이 정한다.
- **D22** (Q21) 헤드리스 실행 권한: 에이전트별 허용 도구만 자동 실행하고 그 밖은 즉시 거부(사람 개입 없음). 기본 옵션
  `--restricted --strict-mcp-config --permission-prompts none` + 권한 모드 명시 + 프로필별 `--tools`. 새 프로필의 기본 허용 도구는
  **읽기 전용(Read · Grep · Glob)** — 확인 답 "읽기 전용 (권장)"(2026-10-11). 넓히는 것은 그 PC 사용자가 프로필에서 — **D31 개정**: 읽기
  전용 목록 안에서만. 루트 `PROJECT.md`

- **D23** (Q22) 대화 = **두 PC 사이**, 발화자 = 양쪽 사람 + 에이전트. Q6 에서는 "1:1 대화만" 만 철회하고 3 PC 이상 다자

- **D24** (Q23) 에이전트 간 자동 왕복: 사람이 대화를 열 때 두 에이전트를 지정하고 첫 메시지를 쓰면 이후 한쪽 답이 다른 쪽

  송신 도구로 스스로 호출(후속) · 자동 왕복 없음.
  **개정(2026-10-11)**: 실행 한도는 **실행 1회당 시간 제한 30분(넘으면 종료)만** — 상대별 시간당 처리 상한 · `--max-turns` ·
  `--max-budget-usd` · PC 전체 동시 실행 상한을 두지 않는다. 확인 답 원문 "한도 없음(시간 제한만)". 대화별 직렬 실행(D19)은

  수신자의 작업에 개입하거나 편집/삭제를 방지한다". 모든 원격 실행에 문의 응답 전용 시스템 프롬프트(`--append-system-prompt`, 개입 ·
