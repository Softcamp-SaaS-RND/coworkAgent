## 의도

- **출처**: 의도 문서 `%APPDATA%\orca\floating-workspace\aitray.md`(2026-10-11 판) +
  [부트스트랩 인터뷰](overview/bootstrap-interview.md).
- **목표**: 해당 프로세스를 실행하고 있는 PC 간 Claude 간 통신할 수 있는 툴 개발.
- **문제**: 같은 claude.ai 계정의 세션끼리는 Claude Code 기본 기능(`SendMessage` + Remote Control)으로 PC 를 넘지만,
  **다른 사용자(계정)의 Claude 에이전트와 대화할 경로는 없다**(계정 간 · LAN 직접 경로 없음, 2026-10-11 조사).
- **비목표**: 파일 전송(텍스트·마크다운만) · 인터넷 너머 연결(허브 경유 포함) · 3 PC 이상 다자 채널 · Linux ·
  Windows ARM64 · 모바일.
- **성공 기준**:
  - SC1: 서로 다른 사용자의 PC 2대(Windows · macOS 각 1대 이상)가 같은 LAN 에서 중앙 서버 없이 페어링하고, 한쪽 사람이
    쓴 메시지에 상대 PC 의 등록 에이전트가 `claude -p` 로 답한다.
  - SC2: 페어링하지 않은 PC 의 메시지는 처리되지 않고, 에이전트에 허용하지 않은 도구는 원격 메시지로 실행되지 않는다.
  - SC3: 대화의 요청/응답 전체가 양쪽 SQLite 에 남고 채팅 모양으로 보이며, 나중에 같은 대화에 이어 쓰면 에이전트가 이전
    맥락으로 답한다.
  - SC4: 두 에이전트의 자동 왕복이 상한에서 멈춘다.
  - SC5: 배포물은 OS 별 실행 파일 1개 — 설치 없이 실행해 트레이 상주 · 자동 실행 · 서명 검증된 자동 업데이트 ·
    `coworkAgent chat` 진입이 동작한다.

## 확정 방향

- **D1** 구현 언어 Rust — Windows·macOS 모두 지원.
- **D2** 단일 실행 파일.
- **D3** 서버/클라이언트를 나누지 않고 단일 실행 파일이 둘 다 제공.
- **D4** 모든 UI 는 웹UI(표시 방식 D9).
- **D5** 개발 flow 는 DDD — 본 문서 체계.
- **D6** 용도는 다른 사용자·PC 간 **에이전트 대화**. 사람의 역할은 D18. 기각안: 사람↔사람 메신저 · 혼합.
- **D7** 피어 발견 = 같은 LAN 자동 발견(mDNS) + 수동 주소(IP:포트), 중앙 서버 없음(사내망 VLAN 멀티캐스트 차단 대비 수동
  추가). 포트 47100 을 못 열면 임의 포트 + 잡은 프로세스(이름 · PID)를 트레이 · 웹UI 에 표시, 페어링된 상대는 `Ping{port}` 로
  (출처 IP, 포트)를 따라간다(페어링 안 된 키는 못 바꿈). **보관 · 재전송 = 보내는 PC 의 SQLite outbox** — 상대별 id 순 전송,
  실패 시 5초부터 두 배 · 최대 5분, 앱이 켜진 동안 24시간 닿지 않으면 그 상대 줄 전부 "보내지 못함"(다시 보내기), 상대에게서
  무엇이든 받으면 즉시 재전송, 받는 쪽 내부 오류는 `retry`, 보낸 쪽은 `Status` 로 상태(대기 · 처리 중 · 끝 · 모름) 질의.
  접속 시각은 통신할 때만 바뀐다(주기 확인 없음) — 시작 때 `announce` 1회, 웹UI 열 때 · 타일 고를 때 확인(60초 안 중복 없음).
  기각안: 허브 경유 · 인터넷 너머 · 메시지 브로커(RabbitMQ 등). 수용한 위험: 페어링을 지운 상대 앞 보관 글도 24시간 재전송 ·
  오래 통신 없던 상대는 켜져 있어도 "n분 전 통신".
- **D8** 신원·보안: 설치별 ed25519 키쌍 + 공개키 고정 TLS, 원격 메시지는 신뢰하지 않는 입력(루트 `PROJECT.md` 가드레일).
  페어링 = 5분 창 · 1회용 초대 코드 — 상대가 초대를 수락하면 생성 측 추가 승인 없이 등록, 아는 키의 다시 추가는 사람 승인.
  한 받기 창에서 출처 IP 당 틀린 코드 10회를 넘으면 그 창 동안 그 IP 의 처음 보는 키 hello 거절. 보완: 등록 즉시 알림(D29) ·
  그룹설정에서 바로 삭제. 수용한 위험(사내망 내부용 — 사용성 우선): 초대 메시지가 새면 창 안에서 제3자 등록 · 주소+코드 직접
  추가는 지문을 고정하지 않아 같은 LAN MITM 이 등록될 수 있다. 기각안: 팀 공유 키 · LAN 신뢰 무인증 · 직접 추가 지문 필수.
- **D9** 웹UI = 내장 웹서버(127.0.0.1 전용) + 기본 브라우저 탭. 실행마다 바뀌는 토큰을 **탭 메모리 + `Authorization: Bearer`**
  로(알림 스트림만 `?t=`) + Host/Origin 검사, 정적 자산은 토큰 없이(Host 검사), 모든 응답에 CSP(`frame-ancestors 'none'`) ·
  `X-Frame-Options` · `nosniff` · `no-referrer`. 기각안: 앱 창(WebView) · 쿠키 토큰(포트를 가리지 않음) · 로컬 API gRPC(공격면
  증가 · 성능 이득 없음 · gRPC-Web 이 D10 과 충돌).
- **D10** 프론트엔드 = 빌드 없는 정적 HTML/CSS/JS(ES modules)를 실행 파일에 임베드 — `cargo build` 하나로 산출. 기각안:
  React/Svelte + Vite.
  (#1z-12 — 2026-10-24 사용자 "권장 방안 승인.") 웹 원본 = `crates/app/web/js/` 의 브라우저 ES 모듈(진입 `app.js` 가 맨 먼저 `core/token.js` — 토큰이 없으면
  거기서 멈춤, 층 `core/` · UI 도메인 · `settings/` · `logic/`), 서버는 내장 표 `SCRIPTS` 로 `/js/{모듈}` 을 준다 — 표의 이름과 정확히 같을 때만 토큰 없이(D9 정적 자산),
  그 밖은 401 · 토큰이 있어도 404. 번들러 · 빌드 단계 없음.
- **D11** 대상 Windows 10/11 x64 · macOS 12+ universal(arm64+x64) 단일 파일. 제외: Windows ARM64 · Linux. mac 빌드는 보유한 Mac.
- **D12** 자동 업데이트 형식 = HTTPS 매니페스트 + 업데이트 파일 서명 검증(앱 자체 ed25519) + 실행 파일 교체. 배포처 ·
  코드 서명(Authenticode · Developer ID)은 D36. (#30 개정 — 2026-10-21 사용자) Windows 검증 = **회사 코드 서명 인증서 Authenticode**(WinVerifyTrust 유효 · 폐기 확인 ·
  서명자 CN `SOFTCAMP CO.,LTD.`) — 앱 자체 ed25519 대신, 매니페스트 = GitHub `releases/latest` 넘겨주기(태그).
- **D13** 자동 실행 기본 ON(첫 실행에 묻지 않음), 켜기 · 끄기 = 웹UI 설정 "시작". 앱이 시작마다 설정 값으로 맞춘다
  (켜짐 = 등록 · 경로 고침, 꺼짐 = 지움). 바꾸기 순서: 켜기 = OS → 저장, 끄기 = 저장 → OS. 디버그 빌드는 등록 없음. Windows
  `HKCU\…\Run` · macOS `~/Library/LaunchAgents/com.coworkagent.plist`(`RunAtLoad`, `KeepAlive` 없음). **비정상 종료 감시**:
  인자 없는 실행 = 감시 프로세스 → 같은 실행 파일을 자식(앱)으로 띄우고 비정상 종료면 1초 뒤 다시, 60초 안 3번이면 멈추고 오류
  트레이(구분 = 환경 변수 `COWORKAGENT_SUPERVISED`). 감시도 잠금(`supervisor.lock`)으로 OS 사용자당 하나 — 앱 시작 실패(코드 3 + 그
  자식이 남긴 사유 파일)는 다시 띄우지 않고 감시가 오류 트레이(하나)를 띄운다. 기각안: 기본 OFF · 트레이 체크 메뉴 · "시작 시 웹UI 열기" 옵션 · OS 서비스 ·
  엔진/트레이 이원화.
- **D14** 실행 파라미터 literal: `coworkAgent`(트레이 상주) · `coworkAgent chat [--peer <사용자ID>]`(대화 UI 로 바로 진입).
  AI 에이전트용 CLI: `coworkAgent peers [--json]` · `coworkAgent ask <상대> "<질문>" [--agent <이름>] [--conv <대화ID>]
  [--no-wait] [--json] [--id <키>]` · `coworkAgent wait <tx>` · `coworkAgent status <tx>` · `coworkAgent history [<상대>]
  [--conv <대화ID>] [--json]` — `<상대>` = 피어 표시 이름 또는 지문 앞자리(겹치면 오류), 인자가 있으면 CLI(앱을 띄우지 않음),
  모르는 명령(`say` 포함)은 종료 코드 2. `--id` 같은 키 재호출은 새로 보내지 않고 그 결과. 기다리는 동안 60초마다 상대에 상태
  질의, 10분 닿지 않으면 **종료 코드 7**(`wait` 로 이어 감), 기다림 상한 24시간. 단일 인스턴스 — 이미 실행 중이면 새 프로세스는
  기존 인스턴스에 요청을 넘기고 종료. 부모 도구 메뉴용: `coworkAgent start [--parent <PID>]` · `coworkAgent open [--parent <PID>]` ·
  `coworkAgent stop` — 꺼져 있어도 동작. 도움말 `coworkAgent /?`(`-h` · `--help`, 첫 인자만 — #1q) = 앱이 꺼져 있어도 명령 · 옵션 · `--json`
  출력 형식 · 종료 코드 · 연동 예를 표준 출력 · 0(다른 AI 도구가 읽고 연동, README "다른 AI 도구와 연동"). `start` · `open` = **트레이 없는 모드**(트레이 · 메뉴 막대 · Dock 없음, `start` 는 브라우저
  안 엶)로 띄우고 받을 준비까지 기다림, 부모(기본 = 부른 프로세스)가 끝나면 함께 정상 종료, 이미 트레이 없는 모드면 그대로(부모도
  처음 것) · 트레이 모드면 끄고 바꿈. `stop` = 앱 · 감시가 끝날 때까지(10초 · 응답 없으면 강제 종료). 종료 코드 8 = 시작 실패. 어떤
  실행 경로로도 앱 · 감시는 하나, 트레이는 많아야 하나. 기각안: 플래그형 `--open-chat` · `start --no-tray` · `stop` 요청만 보내고

  비정상 종료면 실패(적대적 평가 R1).

  세션 함께 · 받은 요청은 다시 넘기지 않음.
