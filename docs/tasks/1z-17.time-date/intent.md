## 범위

- **화면 시각에 날짜** — `formatTime` 을 쓰는 모든 화면(위 호출 전부, 결정 2)이 설정 '날짜 표시방식'(결정 1 · 6)을 따른다. 기본 `M.D HH:MM`.
- **실행 상세 타임라인** '요청 보냄 · 받음' · '응답 받음 · 보냄' 시각 = 같은 방식 + 초(결정 3). 예: 기본 `M.D HH:MM:SS`.
- **세부정보 '대화 정보'** 기간 · 압축 시각 = 같은 방식(앞의 `dayLabel` 을 떼어 날짜 중복 없음, 결정 4).
- **설정 > 화면 '날짜 표시방식'** 칸 — 4가지(결정 6), 서버 설정 저장소에 둔다(다른 화면 설정과 같은 길). 바꾸면 열린 화면 시각이 바로 따른다.
- **설정 실행 · 화면 · 시작 · 알림 · 디버깅** — 설정 타일 1열, 타일 묶음 최대 너비 900px(결정 7 · 8).
- **레일 상태 점** — 큰 타일 14px · 작은 타일 12px(결정 5).
- **설정 > 에이전트 상세** — '저장' 성공 · 실패를 창으로 알림, '삭제' 는 확인 창 승인 뒤에만(결정 10 · 11).
- **에이전트 시스템 프롬프트** — `[수신자 추가 지시]` 를 우리 글의 맨 앞(가드 앞)에(결정 12). Claude · Codex 둘 다.
- 버전 · 매뉴얼([web-ui](../../manual/dev/web-ui.md) · 사용자 가이드 해당 설명) 반영.

## 성공 기준

- A1: `formatTime` 을 쓰는 모든 화면 시각이 '날짜 표시방식' 을 따른다 — 기본 `M.D HH:MM`(다른 해 `YYYY.M.D HH:MM`). 말풍선 위 · 에이전트 답 · 요청 카드 · 요청 의견 ·
  목록 · 활동 · 피어 기록 · 그룹 포함.
- A2: 설정 > 화면에 '날짜 표시방식' 칸 — ① `M.D HH:MM`(기본) ② `오늘 · 어제 HH:MM`, 그 전은 ①과 같음 ③ `YYYY-MM-DD HH:MM` ④ `HH:MM`. ①②는 다른 해면 `YYYY.M.D`.
  고르면 저장되고(다시 열어도 그대로) 열린 화면 시각이 바로 바뀐다. 모르는 값은 서버가 거절한다.
- A3: 실행 상세 타임라인 요청 · 응답 시각 = 고른 방식 + `:SS`(① `10.28 14:03:21` 등). 디버깅 로그 시각은 그대로 `MM-DD HH:MM:SS`.
- A4: 세부정보 '대화 정보' 기간 · 압축 시각 = 고른 방식, 날짜가 겹치지 않는다(① `10.28 16:05`, ② `오늘 16:05`).
- A5: 설정 실행 · 화면 · 시작 · 알림 · 디버깅 타일이 창 너비와 무관하게 1열, 타일 묶음 너비 ≤ 900px(넓은 창에서 이름과 옵션 칸 간격이 900px 안). 디버깅 로그 상자 너비는 그대로.
- A6: 레일 상태 점 = 큰 타일 14px · 작은 타일 12px, 색(대기 · 온라인 · 집중) · 위치(오른쪽 아래 모서리) · 테두리 그대로.
- A7: 그 밖 기존 동작 · 문구 그대로(날짜 구분선 포함), 검증 명령 PASS, 매뉴얼 반영, 버전 1.4.2.
- A8: 에이전트 상세 '저장' 성공 = "에이전트 {이름}을(를) 저장했습니다." 창, 실패 = "에이전트 {이름} 저장 실패: {사유}" 창. '삭제' = 확인 창(이름 · 세션 끊김 안내),
  취소면 지우지 않고 확인이면 지운다.
- A9: 추가 지시가 있으면 시스템 프롬프트(Claude `--append-system-prompt` · Codex `developer_instructions`)가 `[수신자 추가 지시]\n{지시}` 로 시작하고 가드 · 읽기 범위가 뒤에
  그대로 온다. 없으면 가드로 시작(지금과 같음).

## 결정

1. 기본 날짜 형식 = `M.D HH:MM`, 다른 해면 `YYYY.M.D HH:MM` — 사용자 질문 답 U1(Recommended) · 추가 요청 "기본값은 M.D HH:MM". 날짜 구분선 `dayLabel` 의 점 구분과 같은 표기.
   (추가 요청으로 '고정' → 옵션의 기본값으로 개정.)
2. 적용 범위 = `formatTime` 호출처 전부(사이드바 · 홈 목록 시간 칸 포함) — 사용자 질문 답 U2(Recommended). 기각: 목록 칸 제외 · 말한 3곳만.
3. 실행 상세 타임라인 = 날짜 붙임(기본 `M.D HH:MM:SS`) — 사용자 질문 답 U4(Recommended). 날짜 부분은 결정 6 방식을 따른다. 디버깅 로그 시각은 그대로.
4. 세부정보 '대화 정보' = 다른 화면과 같은 방식으로 통일(`dayLabel` 앞붙임 뺌) — 사용자 질문 답 U5(Recommended). 기각: 오늘 · 어제 고정 유지.
5. 레일 상태 점 = 큰 14px · 작은 12px — 사용자 질문 답 U3(Recommended). 기각: 12 · 12 · 16 · 14.
6. 날짜 표시방식 옵션 = 4가지 ① `M.D HH:MM`(기본) ② `오늘 · 어제 HH:MM`(그 전은 ①) ③ `YYYY-MM-DD HH:MM` ④ `HH:MM` — 사용자 질문 답 U6 "4가지(시각만 포함)".
   요청 원문의 "오늘/내일" 은 지난 시각만 보이므로 "오늘/어제" 로 해석(U6 질문에 밝힘). 기각: 2가지 · 3가지.
7. 설정 실행 · 화면 · 시작 · 알림 · 디버깅 = 좌우 분할 없이 1열 — 추가 요청 원문.
8. 최대 너비 900px 대상 = 설정 타일 묶음(`.set-tiles`)만 — 사용자 질문 답 U7 "설정 타일만". 디버깅 로그 상자는 창 너비 그대로(긴 로그 줄). 기각: 화면 전체.
9. 버전 1.4.1 → **1.4.2** — 사용자 "마이너한 기능 업데이트"(권장안 1.5.0 기각).
10. 에이전트 상세 '저장' 완료 창 · '삭제' 확인 창 = 브라우저 기본 창(`alert` · `confirm`) — 추가 요청 2 · 사용자 질문 답 U8(Recommended). 같은 화면 셸 경고와 같은 방식.
    기각: 앱 안 `<dialog>`.
11. 저장 실패도 창으로 — 사용자 질문 답 U9(Recommended). 기각: 성공만 창.
12. 추가 지시 = 우리 시스템 프롬프트 글의 맨 앞(가드 · 읽기 범위 앞) — 추가 요청 3. 구현자 해석: "시스템 프롬프트의 앞" 은 우리가 덧붙이는 글
    (`--append-system-prompt` · Codex `developer_instructions`)의 앞이다 — Claude Code 기본 시스템 프롬프트 앞에 두려면 `--system-prompt` 로 기본 글 전체를
    갈아 끼워야 해 도구 사용 안내까지 사라진다. 가드 문구 · 편집 도구 막음(`--disallowedTools`) · Codex 읽기 전용 샌드박스는 그대로.
13. 설정 타일 드롭다운 = 너비가 가장 긴 옵션 글을 따른다(최소 220px) — 추가 요청 4("드롭다운 리스트의 한글 짤림 방지 수정. 마이너 수정이므로 버전은 변경하지 않음",
    화면 '타일 크기' · '날짜 표시방식' 옵션 글이 220px 고정 칸에서 잘림). 버전 그대로 1.4.2.
