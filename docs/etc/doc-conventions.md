# 문서 규약 — 문서 트리 · 루트 3문서 계약 · Task 폴더 명 · 링크

> **문서를 만들거나 옮길 때 · 루트 `PROJECT.md` · `PRODUCT.md` 의 절이나 원장 형식을 고칠 때 여는 문서.** 절차는
> [ddd-workflow.md](ddd-workflow.md)(매 세션 필독 — 개발 Flow · `STATE.md` 2절), 종결 절차는 그 문서 "개발 Flow" 6. 여기는 문서 구조 계약이며
> `tools/check_ddd_docs.py` 가 기계로 잡는다.

## 문서 체계 (`docs/`)

`docs/` 는 **모든 문서를 담는 단일 트리**. 문서끼리 링크는 **표준 마크다운 상대 경로**로 잇는다.

```tree
docs/
├── masterPlan.md                ← 계약 문서 — 전체 의도·확정 방향(D)·기능 명세(S)·Phase 로드맵
├── tasks/{NN.기능명}/            ← 활성 Task — 문서 체인 일습 (work/stage{M}.md 포함)
├── archive/{NN.기능명}/          ← 종결 Task — `git mv` 한 번으로 이동
├── overview/                    ← ledger.md(미조치 원장 · 누적) + Phase·횡단 보고서
├── manual/                      ← README.md(라우팅·등록 규약) + dev/(개발자·AI) + user/(쓰는 사람)
├── tech/                        ← 횡단 기술 노트·환경 함정 — **개발 전 필독**
├── troubleshootings/            ← 장애 분석 (`{YYYY-MM-DD}-{제목}.md`)
├── feedback/                    ← 사람 작성 피드백
└── etc/                         ← 절차(ddd-workflow) · 의도 프로토콜 · 평가 프로토콜 · 문서 규약(본 문서)
```

- **하나의 Task = 하나의 폴더**(최상위 `plan/`·`work/` 분산 금지) — 횡단 문서만 별도 분기.
- **Task 목록은 폴더가 SSOT.** 상태는 위치(`tasks/`=진행 · `archive/`=종결)와 `report.md` 의
  `⛔ 폐기` 마커로 결정된다 — 같은 내용을 표로 적지 않는다(적으면 반드시 어긋난다).
  목록이 필요하면 `python tools/check_ddd_docs.py --tasks` 로 파생한다.
- 자료는 **단일 위치**에, 이동은 `git mv` 한 번(활성·아카이브 양쪽 복제 금지).
- 분류는 **폴더**, 식별은 **파일명**, 연관은 **상대 링크**, 검색은 **grep**·의존 그래프 — 태그·허브
  문서 대신(일시적 `#TODO` 만 예외).
- **Active vs Archive**: `tasks/{key}/` = 진행 중, `archive/{key}/` = 종결(개발 Flow 6 을 마친 Task —
  `report.md` 가 그 표지다). **폐기**는 `report.md` 에 `⛔ 폐기` 를 적는다 — 미착수(`work/stage*.md`
  없음)면 체커가 plan·eval·gate·환류 규약을 면제하고, 착수 후 폐기는 남은 gate 를 전부 `ABANDON:`
  으로 드러낸 뒤 종결한다.
- **문서 규약 체커(필수)**: `tools/check_ddd_docs.py` 가 링크·디렉토리·계약·gate·원장을 기계로
  잡는다 — 검사 목록의 정본은 그 파일의 docstring. **빌드·테스트 green 과 별개**로 통과해야 종결한다.

## 루트 3문서 계약

프로젝트 고유 요소는 **역할로 갈린다** — 뼈대는 절차만 정의하고, 절차가 소비하는 데이터는 이 셋이
공급한다. 어느 문서든 **빈 절은 없다**: 실내용이 없으면 `없음`, 미확정이면 `미확정` + TODO 주석.
근거 없는 문장으로 칸을 메우지 않는다. `check_ddd_docs.py` 가 아래 목록으로 검사하므로, 목록을
바꾸려면 **본 절과 체커를 동시 개정**한다.

| 문서 | 담는 것 | 갱신 시점 |
|------|---------|-----------|
| `PROJECT.md` | 어떻게 일하는가 — 가드레일 · 개발 환경 · 검증 | 결정이 바뀔 때 |
| `PRODUCT.md` | 무엇을 만들었는가 — 구조 · 규칙 · 설계 | 모듈·규칙이 바뀐 Task 종결 시 |
| `STATE.md` | 지금 어디인가 — 재개 좌표 (**전부 덮어쓴다**) | 단계 전환마다 |

`STATE.md` 2절 계약은 단계 전환마다 쓰므로 [ddd-workflow.md](ddd-workflow.md) "STATE.md — 필수 2절" 에 둔다.

### PROJECT.md — 필수 5절

| # | heading | 정의 |
|---|---------|------|
| 1 | `## 치명 가드레일` | 지켜야 산출물이 유효한 계약 — 3~7줄, 문서 최상단. 체커가 줄 수·자리별 키워드 고정 |
| 2 | `## 프로젝트 개요` | 목표 한 문장·성격. 전체 의도·범위·제외는 masterPlan `## 의도` 가 정본(복제 금지) |
| 3 | `## 개발 환경` | 도구 전제(역할 표의 수단) · Git 브랜치 전략 |
| 4 | `## 검증 명령` | 커밋·종결 전 PASS 필수 명령의 정확한 호출형 표 |
| 5 | `## 참조 문서` | 루트 문서 · 계약 문서 · 필독 노트 · 피드백 위치 |

권장(비필수): 저장소 레이아웃 / 설정·시크릿 2-tier / 적대적 평가 사례.

- 가드레일은 3 ~ 7줄, 문서 최상단. 🔴 "무엇이 변하면 안 되는가" 로 쓴다 — "어느 파일을 건드리지 마라" 는 경로가 사라지는 순간
  검사도 사라진다(영원히 초록). 줄 수 · 자리별 키워드는 `tools/check_ddd_docs.py` 의 `GUARDRAIL_BULLETS` · `GUARDRAIL_KEYWORDS` 와 함께 고친다.

### PRODUCT.md — 필수 6절

제품 문서에 프로세스를 섞지 않는다(도구·브랜치·Task 현황은 여기가 아니다).

| # | heading | 정의 |
|---|---------|------|
| 1 | `## 제품 개요` | 무엇을 하는 제품인가 한 문장 + 입출력·외부 인터페이스 경계 |
| 2 | `## 기술 스택` | 언어·런타임·핵심 의존·빌드·테스트(러너·경로·경고 baseline) |
| 3 | `## 모듈 Layer 구조` | 실측 layer 표 + 의존 방향 + 의존 경계 규칙 (`check_layers.py` 가 이 표를 읽는다) |
| 4 | `## 도메인 규칙` | 제품 고유 규칙 (공통 원칙은 본 문서) |
| 5 | `## 개발된 모듈 / 매뉴얼` | 모듈·상태·의존(실측)·매뉴얼 링크 표 |
| 6 | `## 설계 문서` | 매뉴얼 라우팅 · 기술 노트 등 설계 자료의 링크 인덱스 |

### 미조치 원장 — [overview/ledger.md](../overview/ledger.md)

Task 를 가로질러 **누적**되는 유일한 기록. 상태 전이(`열림`→`닫힘`·`수용`)와 `마지막 확인` 은 폴더나
문서 체인에서 파생되지 않으므로 전용 문서를 갖는다. 5열(출처 · 요지 · 판단 · 상태 · 마지막 확인) ·
상태 어휘 5값 고정 · 종결 Task 의 `eval.md` `## 미조치 지적` 표와 대조된다(체커).

## Task 폴더 명

- canonical key = `{NN}.{기능명}`. NN 버퍼는 [masterPlan.md](../masterPlan.md) 기준(Phase 0 = `00~09`,
  Phase 1 = `10~19`, …). 번호는 Task 의 **주소**다 — 같은 번호 둘은 위반(`24` 와 `24-2` 는 다른 주소,
  `-n` 은 같은 번호의 하위 트랙).
- 🔴 **앞자리 0 은 주소가 아니다** — `#00`·`#0`·`000` 은 **같은 번호**다(체커가 정규화한다). 자리수를
  늘려 새 주소를 만들 수 없다. `000.무엇` 같은 세 자리 이름은 `00.무엇` 과 충돌하고 번호 중복으로
  FAIL 한다. 버퍼가 모자라면 자리수가 아니라 오버플로(아래 소문자 한 글자)를 쓴다.
- **NN 은 진짜 신규 작업에만.** 검증·리뷰·하우스키핑처럼 새 산출물이 없는 작업은 Task 폴더를 만들지
  않고 대상 Task 문서나 `docs/tech/`·`docs/troubleshootings/` 에 남긴다.
- **버퍼는 Phase 당 10개.** 소진 시 오버플로(`0a~0z` — 숫자 뒤 **소문자 한 글자**, 체커가 읽는 유일한
  확장)를 [masterPlan.md](../masterPlan.md) 에 **미리** 적어 둔다. 11번째에서 임기응변하면 canonical key 가
  흔들린다.

## 링크 (표준 마크다운)

- `docs/` 내부 참조는 **표준 마크다운 상대 경로**(`[텍스트](../etc/eval-protocol.md)`). 외부 URL 은
  `[text](https://…)`. 이중 대괄호 표기(wikilink)는 금지 — 백틱·울타리 안이라도 위반이다.
- 같은 Task 폴더 내 형제 참조는 **파일명만**(`[plan](plan.md)`, `[stage1](work/stage1.md)`). archive 로
  옮겨도 상대 관계가 유지된다.
- **다른 Task 를 가리킬 때**는 상대 경로(`../04.someTask/report.md`). **종결 시 인바운드 링크를
  `archive/{key}/…` 로 함께 갱신**한다. 가능하면 `report.md` 를 가리켜라 — 종결 후에도 의미가 유지되는
  유일한 문서다.
- 🔴 **링크는 휘발성 → 안정 방향으로만.** 안정 문서(`tech/`·`manual/`·`masterPlan.md`)는 휘발성 문서
  (`tasks/`)를 **가리키지 않는다** — 종결마다 갱신 부담이 생기고 놓치면 dead link 다. 남길 값이 있으면
  링크가 아니라 **그 문서로 내용을 옮긴다**. 활성 Task 목록을 링크 표로 만들지 않는다 — 폴더가
  SSOT 이고 목록은 `python tools/check_ddd_docs.py --tasks` 로 파생한다.
- **현존 문서는 링크로.** 백틱 경로는 코드 파일과 삭제된 역사 경로에만.
- **루트 문서**(`CLAUDE.md`·`PROJECT.md`·`PRODUCT.md`·`STATE.md`)는 `docs/` 밖이다. `docs/` 안에서는 백틱으로
  **루트 `PROJECT.md`** 처럼 쓴다. 코드 docstring·문서 밖 인용은 **주제명으로** — 섹션 번호는 개정 때
  전량 어긋난다.
