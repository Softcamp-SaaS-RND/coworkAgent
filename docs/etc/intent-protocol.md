# 의도 프로토콜 — intent.md · 인터뷰 · 환류

> **Task 를 여는 시점과 종결 환류 시점에만 여는 문서.** 절차는 [ddd-workflow.md](ddd-workflow.md)
> "개발 Flow" 2·6,
> 평가 쪽 짝은 [eval-protocol.md](eval-protocol.md). 여기는 `intent.md` 의 형식과 인터뷰·승인·
> 환류 규약이며 `tools/check_ddd_docs.py` 가 섹션·승인 줄을 기계로 잡는다.

`intent.md` 는 그 Task 의 **무엇·왜** 의 단일 기록이다 — 방법(어떻게)은 `plan.md`.

## 규약

1. **seed 는 누구나 쓴다**(Originator — 사용자·기획·리뷰어·다른 세션). 요청 한 단락 + 출처면
   충분하다. 출처 = [masterPlan.md](../masterPlan.md) 의 D·S 번호 / `docs/troubleshootings/` 노트 /
   `docs/feedback/` / 대화. seed 만 있는 상태는 `승인: 대기` 다.
2. **AI 가 인터뷰로 채운다** — 수단은 [ddd-workflow.md](ddd-workflow.md) "도구 전제"(`grill-me`). 이름이 아니라
   **역할**이 계약이다:
   - **프런티어를 라운드로 묻는다.** 이미 정해진 것에만 기대는 질문을 한 라운드에 전부,
     번호 + **권장안**. 다른 열린 질문에 기대는 질문은 다음 라운드.
   - **사실은 AI 가 찾는다**(코드·의존 그래프·문서·로그). 사용자에게는 **결정**만 묻는다.
   - **라운드마다 intent.md 에 적는다** — 결정은 `## 결정` 에, 열린 것은 `## 미해소` 에.
     기억이 아니라 문서가 인터뷰의 상태다(세션이 끊겨도 이어진다).
   - 종료 = 프런티어가 비었고 사용자가 **"공유 이해 도달"** 을 확인 → `승인: {YYYY-MM-DD}`.
     그 확인이 곧 intent 승인이다(별도 승인 절차 없음).
   - 🔴 **5 라운드를 넘기면 Task 를 쪼갠다.** 수렴하지 않는 인터뷰는 Task 가 둘 이상이라는
     신호다(gate 20개 → 쪼갠다와 같은 축).
3. **필수 6 섹션** — heading 글자 그대로(괄호 부연만 허용), 본문은 비우지 않는다(없으면 `없음`).

   | heading | 담는 것 |
   |---|---|
   | `## 왜` | 문제·요청·출처(D·S 번호 인용). 이 Task 가 없으면 무엇이 안 되나 |
   | `## 범위` | 한다 — 대상·경로·산출물 |
   | `## 제외` | 하지 않는다 — 의사결정 비용을 줄이는 명시적 경계 |
   | `## 성공 기준` | 번호 매긴 **검증 가능한 결과**(`A1`, `A2`, …). plan 의 gate `E*` 가 전부 덮는다 |
   | `## 결정` | 인터뷰에서 확정한 결정 — 선택·기각안·이유. 프로젝트 수준이면 종결 시 D 로 승격 |
   | `## 미해소` | 열린 질문 + 권장안. plan 승인 전 해소하거나 `## 제외` 로 옮긴다. 남기면 plan 이 가정을 명시 |

4. **plan 은 intent 를 덮는다.** `plan.md` `## 평가 항목` 의 gate 가 `## 성공 기준` 을 **전부**
   덮는다(기계 판정이 어려우면 수동 gate 로라도). 대응은 **gate 제목 첫머리에 `A{n}` 을 적어** 드러내며
   — `- [ ] E3: A2 회귀 없음` · 둘 이상이면 `A1·A3 …` — `tools/check_ddd_docs.py` 가 A 번호 집합을
   대조해 **덮이지 않은 기준을 FAIL** 로 잡는다. 체커는 번호를 **자리**로 읽는다: 기준은 `- A1: …` 줄,
   대응은 제목 첫머리뿐(산문 속 "A4 용지" 는 번호가 아니다). 번호가 없으면 그것도 FAIL.
   기준을 범위 밖으로 미는 것은 intent 개정(사용자 승인)으로만 — 조용한 축소 금지. 체커가 보는
   것은 *대응 표시*이지 gate 가 실제로 그 기준을 재는지가 아니다 — 그 판정은 여전히 적대적
   평가자의 첫 질문이다([eval-protocol.md](eval-protocol.md) 규약 6).
5. **종결 시 masterPlan 으로 환류한다** — 내용을 옮긴다, 링크가 아니라(안정 문서는 Task 를
   가리키지 않는다 — [doc-conventions.md](doc-conventions.md)).
   - `## 결정` 중 프로젝트 수준 결정 → masterPlan `## 확정 방향` 에 D 추가·개정. 구현이 명세를
     바꿨으면 S 를 개정한다.
   - masterPlan `## 개정 기록` 에 한 줄(날짜 · Task #N · D/S 번호 · 무엇을). 종결한 Task 의
     `#N` 줄이 없으면 `tools/check_ddd_docs.py` 가 FAIL 한다 — 옮길 것이 없었다면 그 사실을
     한 줄로 적는다(“봤고 없었다” 와 “안 봤다” 를 가르는 유일한 기록).
   - 인용할 D·S 가 없었다면 intent 자체가 masterPlan 개정 후보다 — **먼저** masterPlan 을 고치고
     (사용자 승인) 인용한다. masterPlan 에 없는 일을 Task 가 조용히 만들지 않는다.
6. **intent 는 종결 뒤에도 그 자리에 남는다.** `docs/tasks/*/intent.md`·`docs/archive/*/intent.md`
   를 grep 하면 전 Task 의 의도가 모인다(`grep -rl "S3" docs/*/*/intent.md` = S3 를 실현한 Task —
   인용이 없는 D·S 는 아직 실현되지 않은 것). **전체** 의도·명세는 masterPlan, **Task 별** 의도는
   intent.md, **목록**은 폴더(`--tasks` 파생). 셋을 복제하지 않는다.

## intent.md 골격 (복사해서 시작)

```markdown
# intent — {NN.기능명}

승인: 대기

## 왜
{문제·요청 한 단락} — 출처: {masterPlan D·S 번호 / 노트 링크 / 대화}

## 범위
- {한다}

## 제외
- {하지 않는다}

## 성공 기준
- A1: {검증 가능한 결과}

## 결정
- 없음 (인터뷰 전)

## 미해소
- {열린 질문} — 권장안: {…}
```

- `승인:` 줄은 **정확히 하나**, 열 0 에 둔다. `plan.md` 가 있는데 `승인: 대기` 이거나 줄이 없으면
  체커가 FAIL 한다 — 의도가 확정되기 전에 방법을 쓴 순서 역전이다.
