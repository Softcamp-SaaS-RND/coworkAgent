## 왜

'나' 의 '내 활동' 과 '주고받은 메시지' 는 거의 같은 글을 보여 메뉴 둘이 겹쳐 보이고, 주고받은 메시지는 글이 쌓이면 한 화면에 너무 많이 나온다.
— 출처: masterPlan D35(사이드바 메뉴 — 내 활동 · 요청 · 주고받은 메시지) · S4(웹UI). 대화(2026-10-18) 사용자 지시 "문서 내용 확인하고 개발 진행해." —

코드 사실(2026-10-18 조사):

- **요청 화면** = `index.html` `#requests` — 탭 `#req_tab_theirs` "받은 요청"(기본) · `#req_tab_mine` "보낸 요청" + 상태 거르기 `#req_state`(전체 · 대기 · 수용 · 반려 · 완료).
  `app.js` `loadRequests` 가 `state.reqBox` 한쪽만 `GET /api/messages?side={box}&ask=request` 로 받는다(기본 limit 200 · 최대 500).
  '나' 범위면 `grouped()` 가 이미 상대별 접이식 절(`<details class="peer-fold">`, 머리 "{상대} · {건수}", 접힘은 `ui_folded`)로 나눈다 — 상대 · 그룹 타일은 한 목록.
  → 없는 것은 (가) 받은 · 보낸 **바깥 단계** 와 그 건수, (나) 들어갔을 때 **둘을 함께** 보이기.
- **수용 · 반려 단추**는 두 곳에 있다:
  - 요청 목록 `requestEls` — 행 `<a>`(이름 · 상태 태그 · 시각 · 대화 제목 / 본문 앞부분 / 메모 / "요청자에게 알리지 못함") **뒤** 형제 `div.actions`,
    `app.css` `.actions { justify-content: flex-end }` → 우하단. 단추는 기본 `button`(크기 · 색 무지정). 누르면 같은 자리에 `noteForm`(메모 한 줄 · 확인 · 취소).
  - 대화 말풍선 `.msg-actions` — 말풍선 위 떠 있는 붙은 단추 묶음(호버 때만, 높이 30px · `--fs-xs` · 무채), 좁은 화면(≤ 720px)은 말풍선 아래 고정.
  - 세부정보 패널 '요청' 절은 목록만(단추 없음).
  - 단추는 `<a>` 안에 넣을 수 없다(HTML) — 행 링크 밖 형제로 두고 자리만 옮긴다.
- **내 활동**(`#activity`, '나' 에만) = `core/src/chat.rs` `activity` — 상대 쪽 글 **전부**(사람 메시지 · 에이전트 답, 공유 사본 제외) + 내 쪽 실패 글 +
  자동 왕복 시작 · 끝 + 상대 반영 실패. 종류 거르기(전체 · 사람 메시지 · 에이전트 답 · 자동 왕복 · 실패) · 본문 검색 · 안 본 강조, 안 본 수 = 사이드바 배지 · 상단 종 점.
- **주고받은 메시지**(`#p`, '나' 에만) = `loadPeerMessages` — 상대 쪽 + 내 쪽 글을 최신순으로 합쳐 **최대 200건**, 상대별 접이식 절(기본 펼침), 줄 = 상대 타일 ·
  이름 · 에이전트 칩 · 시각 · 대화 제목 · 요청 태그 · 본문 앞부분.
  - 겹침: 내 활동의 글 행 ⊂ 주고받은 메시지(상대 쪽 글이 둘 다에 나온다). 다른 점은 내 쪽 정상 글(주고받은 메시지만) · 자동 왕복 · 실패 기록 · 안 본 표시(내 활동만).
  - `view.js` `sideNav` 주석: 상대 · 그룹 타일에 주고받은 메시지가 없는 이유 = "대화방 목록이 같은 글을 보인다".
- **요청 상태 바뀜**(내가 보낸 요청이 상대에게서 수용 · 반려 · 완료됨)은 지금 내 활동 · 알림 어디에도 기록이 없다 — 내 글 `req_state` · `req_at` 만 바뀐다.
- **내 활동 안 본 표시**는 id 기준이다 — 상대별 `activity_seen_msg`(글 id) · `activity_seen_event`(`relay_events` id). 요청 상태가 바뀌면 내 글의
  `req_state` · `req_note` · `req_at`(`core/src/chat.rs` `UPDATE … req_at = unixepoch()`)만 바뀌고 새 id 가 없다 → 상태 바뀜을 "안 본 것" 으로 잡으려면 기록이
  필요하다. `relay_events.kind` 는 CHECK 없는 TEXT 라 새 종류(`req_state` 등) 행을 **스키마 변경 없이** 넣을 수 있다(`db.rs` 190).
- **`GET /api/messages`**(`MessageQuery`) = `side`(theirs | mine 하나) · `peer` · `group` · `q` · `kind` · `ask` · `req` · `limit`(기본 200 · 최대 500) — 커서(이전 페이지)
  · 상대별 전체 건수는 없다. 주고받은 메시지 "더 보기" 를 200건 너머로 하려면 서버 보강이 필요하다.
- 화면 규칙 제약: `app.css` 는 `:root` 밖에서 `var(--…)` 만(`tests/css_tokens.rs`), 문구 규칙(이름 = 명사 하나 · 빈 화면 "{무엇} 없음") · 잠금 `tests/ux_literals.rs` ·
  `view.test.mjs`([웹UI 화면 규칙](../../manual/dev/web-ui.md) 문구 규칙 · 용어 표).

## 범위

- **요청 개요**: '요청' 메뉴로 들어가면 받은 요청 · 보낸 요청을 아코디언으로 함께, 절 머리에 전체 건수와 상태별 건수(대기 · 수용 · 완료 · 반려). 탭은 남기고, 누르면
  그 목록만.
- **요청 단추**: 요청 목록의 상태 바꾸기 단추를 본문 바로 다음 줄에 글자 단추(아이콘 + 글자)로.
- **내 활동**: 받은 요청 · 내 요청(상태 대기 · 수용 · 완료 · 반려) · 받은 답 · 실패만. 자동 왕복 · 상대 사람의 일반 메시지는 뺀다. 안 본 수(종 · 사이드바 배지)도 같은 범위.
- **주고받은 메시지**: 상대별 절 기본 접힘 + 머리 요약 + 20건씩 더 보기, 행마다 북마크 넣기 · 빼기.
- (개정) **CLI 도움말**: `coworkAgent.exe /?` 가 CLI 명령 · 옵션 · 출력 형식 · 종료 코드를 출력한다. README 에 다른 AI 도구가 `/?` 로 확인하고 연동하는 법.
- 동기화: 사용자 가이드 · 매뉴얼(web-ui · an_app) · masterPlan D35 · S4 환류.

- A6: 주고받은 메시지가 상대별 절 기본 접힘 · 머리 요약으로 보이고, 펼치면 20건씩만 그린다(더 보기).

14. **북마크 컨트롤** = 행 오른쪽 북마크 아이콘(말풍선과 같은 그림 · 동작 · 늘 보임 · 켜면 강조).

개정(2026-10-18, 위 개정 승인 지시):

15. **CLI 도움말** — 첫 인자 `/?`(지시 글자 그대로)와 관례 `-h` · `--help` 가 같은 도움말(해석 — `--help` 를 먼저 시도하는 AI 도구가 많아 함께 둔다).
    첫 인자일 때만(다른 자리의 `/?` 는 `ask` 본문일 수 있다). 출력 = 한 줄 소개 + 기존 사용법(`cli::USAGE`) + 출력 형식(`--json` 꼴 · 표준 출력 / 오류) ·
    종료 코드 0 ~ 8 · 연동 예. 표준 출력 · 종료 코드 0 · 앱 불필요. README "다른 AI 도구와 연동" 절 + 사용자 가이드 §14.
