02 는 인바운드 알림을 Windows 전용 WinRT 토스트(+ macOS AppleScript)로, 00 은 시작 실패를 Windows 메시지 상자로 띄웠다 — 두 OS 의
UI/UX 가 갈린다. 사용자 지시 원문 "네이티브 종속성이 없는 방향이 맞어. 왜냐하면 동일 기능과 ui/ux 로 mac에서도 동작해야하기
때문이야." — 출처: [masterPlan](../../masterPlan.md) D30 · D27 · D29 · S9 · 가드레일 4행 · 확인 답(2026-10-11 "브라우저 알림 + 트레이 표시" ·
"트레이 오류 모드").

## 범위
- 인바운드 알림을 브라우저 알림(웹UI 탭이 열려 있을 때, 서버 → 웹UI 이벤트 스트림) + 트레이 아이콘 · 툴팁 "새 요청" 표시로 바꾼다
- 시작 실패를 트레이 오류 모드(오류 아이콘 · 툴팁 · "오류 보기" · "종료")로 바꾼다
- WinRT 토스트 · AUMID 레지스트리 · AppleScript 알림 · 메시지 상자 코드와 그 의존(`windows` · 레지스트리 · 메시지 상자 기능)을 걷어 낸다

## 제외
- 원격 메시지 알림 — 04.agent-roundtrip(같은 이벤트 경로)
- 웹UI 탭 없이 브라우저 알림(서비스 워커 · 푸시) — 로컬 전용 서버라 푸시 서비스가 없다
- 수동 확인(브라우저 알림 실표시 · 트레이 표시 · 오류 모드) — D28

## 성공 기준
- A1: 알림이 켜져 있으면 인바운드 이벤트가 웹UI 이벤트 스트림으로 전달되고 트레이 "새 요청" 건수가 오른다. 꺼져 있으면 둘 다 없다.
- A2: 웹UI 가 이벤트 스트림에 붙거나 트레이에서 웹UI 를 열면 "새 요청" 표시가 지워진다. 알림을 끄면 표시도 지워진다.
- A3: 이벤트를 읽지 않는(느린) 웹UI 가 있어도 피어 수신 처리가 막히지 않는다.
- A4: 시작이 실패하면 사유를 담은 오류 파일이 생기고 트레이 오류 모드로 뜬다(파일 내용은 자동, 트레이는 수동 — D28).
- A5: 앱 코드에 OS 전용 UI API(WinRT · 메시지 상자 · AppleScript · 레지스트리)가 없다 — 의존 목록과 코드 검색으로 단정한다.
- A6: 루트 `PROJECT.md` 검증 명령의 테스트 · 경고 0 · 의존 경계 행이 통과한다.

## 결정
사용자 지시 · 확인 답 + 자동 진행 위임.

- X1 서버 → 웹UI 는 SSE(`GET /api/events`, `text/event-stream`, guard 뒤) — 기각: WebSocket(양방향 불필요 · 의존 추가).
- X2 브라우저 알림 권한은 알림 설정을 켜는 순간(사용자 동작) `Notification.requestPermission()` — 거부되면 트레이 표시만 남는다고 안내.
- X3 트레이 표시: 건수 > 0 이면 아이콘에 주황 점 + 툴팁 "agentNetwork — 새 요청 N건". 트레이 갱신은 이벤트 루프 프록시로(막히지 않음).
- X4 오류 파일은 사용자 임시 폴더 `agentNetwork-start-error.txt`(데이터 경로가 원인일 수 있어 그 밖) — "오류 보기" 는 OS 기본 앱으로 연다
  (Windows `ShellExecuteW` ↔ macOS `open`, D30 의 허용 연동).
- X5 이벤트 배포는 `tokio::sync::broadcast`(가득 차면 오래된 것을 버림 — 느린 구독자가 보내는 쪽을 막지 않는다).
