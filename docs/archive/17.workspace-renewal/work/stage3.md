## 목표

Stage 2 가 놓은 마크업 · view 함수를 app.js 에 잇는다 — 대화 머리글 ★ · 부제 model/effort, 메시지 작업(저장 · 복사 · 다시 보내기), 실행 상세
(진행 · 대화 정보 · 자동 왕복 · 저장된 항목), 저장된 항목 · 에이전트 화면, 통합 검색 결과와 이동(`#c/{대화}/m/{글}` 위치 포함). 대상 gate: E3 · E11
(건수는 그대로 — plan 편차 2 로 E3 31건을 Stage 2 에서 채웠다).

## 설계 결정

- **실행 기본값(대화 정보)** — 받은 대화는 이 PC 가 실행하므로 상대별 덮어쓰기 → 전역 설정 → 기본값(sonnet · high, 15 규칙). 보낸 대화는 상대 PC
  설정이 정해 이 PC 는 모른다 → 마지막 답의 값이 있으면 "{model} · {effort} — 마지막 실행", 없으면 "상대 PC 가 정함"(시안은 값만 보였으나 이 PC 가 아는
  사실만 보인다).
- **실행 중 경과** — 실행 시작 시각은 남지 않는다(해석 6) → 받은 때부터의 초(대기 포함). 받은 쪽(실행하는 쪽)의 요청 글에만 — 보낸 쪽은 상대의 실행을
  모른다.
- **실행 상세의 저장된 항목** — 이 대화 글의 `saved` 표시로 그린다(새로 고침마다 API 를 더 부르지 않는다), 최근 글부터. 저장된 항목 화면은 API
  (저장 순).
- **자동 왕복 표시** — 머리글의 기존 표시 · 버튼은 그대로 두고(실행 상세를 닫아도 멈출 수 있게) 실행 상세에도 같은 API 로.
- **에이전트 화면 '나' 범위** — 상대 PC 마다 원격 왕복이라 화면을 열 때 아직 없는 것만 받고, 받는 대로 다시 그린다("불러오는 중 …" · "목록을 받지
  못했습니다").
