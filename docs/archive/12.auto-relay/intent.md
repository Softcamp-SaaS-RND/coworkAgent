# intent — 12.auto-relay

승인: 2026-10-11 (자동 진행 위임 + 확인 답 2건)

## 왜

D24(에이전트 간 자동 왕복) — 사람이 대화를 열 때 두 에이전트를 지정하고 첫 메시지를 쓰면 이후 한쪽 답이 다른 쪽 입력으로 자동 전달되고,
대화당 자동 왕복 상한 10(설정 가능)에서 멈춰 사람 입력을 기다린다. 지금은 사람 → 원격 에이전트 왕복과 양쪽 사람 발화(11)까지만 있다.
— 출처: masterPlan D24 · S1, 확인 답(2026-10-11) "양쪽이 한 번씩 답하면 1" · "양쪽 사람 모두 (권장)".

## 범위

- 새 대화를 열 때 **내 에이전트**(이 PC)를 함께 고르면 자동 왕복 대화가 된다 — 상대 에이전트 답이 오면 내 에이전트가 그 답을 입력으로
  실행하고, 그 답을 상대 에이전트에게 실행 요청으로 보낸다. 반복.
- **상한**: 대화마다 설정(기본 10). 1왕복 = 내 에이전트가 상대 답에 한 번 답한 것(양쪽이 한 번씩 답함). 상한에 닿으면 멈추고 사람 입력 대기.
- **멈춤**: 양쪽 사람 모두 — 멈춤 버튼, 또는 사람이 그 대화에 글을 쓰면(어느 쪽이든) 멈춘다. 받은 쪽이 멈추면 그 PC 는 이후 에이전트발
  실행 요청을 거절한다(받은 쪽 사용량은 받은 쪽이 끊는다). **재개**는 대화를 연 쪽이 — 카운트를 0 으로.
- 에이전트발 글은 양쪽 이력에 에이전트 글로 남는다(누구의 에이전트인지). 받은 쪽 실행 입력에도 "상대 에이전트의 요청" 으로 표시.
- 웹UI: 새 대화에 "내 에이전트로 자동 왕복"(선택) · 상한, 대화 머리글 "자동 왕복 n / 상한" · 멈춤 · 재개.

## 제외

- 에이전트가 송신 도구로 스스로 상대를 부르기(D24 기각안 — 후속).
- 3 개 이상 에이전트 · 다자.
- 실화면 · 실제 `claude -p` 확인 — `19.prototype-acceptance`(D28).

## 성공 기준

- A1: 자동 왕복 대화에서 상대 에이전트 답 → 내 에이전트 실행 → 그 답이 상대 에이전트 실행 요청으로, 상한(n 왕복)에 닿을 때까지 반복되고
  멈춘다. 양쪽 이력에 같은 순서로 남는다.
- A2: 어느 쪽 사람이든 멈춤을 누르거나 그 대화에 글을 쓰면 자동 전달이 멈춘다. 받은 쪽이 멈추면 그 PC 는 에이전트발 실행 요청을
  `stopped` 로 거절한다.
- A3: 대화를 연 쪽이 재개하면 카운트 0 에서 다시 자동 전달하고, 받은 쪽 거절도 풀린다.
- A4: 에이전트발 실행 요청은 페어링 · 대화 소유 · 가드(D31) 규칙을 그대로 따른다.
- A5: 루트 `PROJECT.md` 검증 명령이 통과한다.

## 결정

- 왕복 셈: 내 에이전트가 상대 답에 한 번 답하면 1 — 확인 답 "양쪽이 한 번씩 답하면 1". 기각안: 자동 전달 1회 = 1.
- 멈춤: 양쪽 사람 모두 · 사람이 쓰면 멈춤 — 확인 답. 기각안: 연 쪽만.
- 재개는 연 쪽만(받은 쪽 거절도 그때 풀림), 상한 기본 10 · 1 ~ 50 — 권장안(자동 진행 위임).
- 자동 왕복은 대화를 연 PC 가 구동한다(상대 답 수신 → 내 에이전트 실행 → 실행 요청 전송) — 권장안.
