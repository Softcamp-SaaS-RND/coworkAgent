## 왜

다른 툴(부모 프로세스)이 자기 하위 메뉴로 coworkAgent 의 실행 · 열기 · 종료를 제공하려 한다. 지금은 띄우면 늘 트레이 아이콘이 생기고, 끄는 방법은 트레이
"종료" 뿐이며, 이미 떠 있을 때 실행 파일을 다시 부르면 화면이 열린다 — 부모 툴 메뉴가 주인이 될 수 없다.
중복 실행은 단일 인스턴스 잠금(D14)으로 대부분 막지만 빈틈이 있다 — 시작 실패 · 화면 넘기기 실패 때의 오류 트레이(D30)는 잠금 없이 남아 실행할 때마다
하나씩 늘 수 있고, 동시에 여러 번 실행하면 감시 프로세스(#1e)가 그 수만큼 뜬다.

## 범위

- **트레이 없는 모드** — 트레이 아이콘 없이 앱(피어 수신 · 에이전트 실행 · 웹UI 서버)만 돈다. 감시 프로세스(#1e)는 그대로 비정상 종료를 다시 띄운다.
  부모 프로세스가 끝나면 앱 · 감시 모두 정상 종료한다.
- `coworkAgent start [--parent <PID>]` — 트레이 없는 모드로 띄우고 받을 준비가 될 때까지 기다린 뒤 성공. 화면(브라우저)은 열지 않는다.
  - 이미 트레이 없는 모드로 떠 있으면 아무것도 하지 않고 성공(부모는 처음 것 그대로).
  - 이미 트레이 모드로 떠 있으면 그것을 정상 종료하고 트레이 없는 모드로 다시 띄운다(잠깐 끊김).
  - 부모 = 기본은 `start` 를 부른 프로세스, `--parent <PID>` 로 지정(셸을 거쳐 부르는 툴).
- `coworkAgent open [--parent <PID>]` — 떠 있으면 화면을 연다(트레이 "열기"). 꺼져 있으면 `start` 와 같이 띄운 뒤 연다.
- `coworkAgent stop` — 트레이 "종료" 와 같은 정상 종료(두 모드 모두). 앱 · 감시가 모두 끝날 때까지(최대 10초) 기다린다. 이미 꺼져 있으면 바로 성공.
  오류 트레이(시작 실패 · 감시 멈춤)도 끈다.
- 트레이 없는 모드의 오류 — 트레이가 없으므로 `start` · `open` 이 0 이 아닌 코드와 사유(표준 오류)로 알린다. 사유 파일은 지금처럼 남긴다.
- 중복 실행 방지 — 어떤 실행 경로(인자 없는 실행 · `start` · `open` · 자동 시작 · 감시의 다시 띄우기 · 동시 실행)에서도 앱 · 감시 프로세스는 하나,
  트레이(오류 트레이 포함)는 많아야 하나.
- 인자 없는 실행 · 로그인 자동 시작은 지금처럼 트레이 모드. 인자 없는 두 번째 실행은 떠 있는 앱의 화면을 연다(모드 무관).
- 종료 코드 · 사용법 문구는 기존 CLI(#16 · #1c) 규약을 따른다. 사용자 가이드 §14 · 개발자 가이드 · README · D14 literal.
- Windows · macOS 같은 동작(D30).

## 제외

- 트레이 없는 모드의 "새 요청" 표시(트레이 S9) — 브라우저 알림(D30)은 그대로 온다. 부모 툴에 개수를 넘기는 명령은 요청 밖.
- `restart` · 상태 조회 같은 추가 운영 명령 — 요청 밖(기존 `status` 는 CLI 트랜잭션 조회 그대로).
- 다른 OS 사용자 계정의 인스턴스 제어 — 데이터 경로 · 잠금이 사용자별이다(그대로).
- 종료 전 실행 중 작업을 끝까지 기다리기 — 트레이 "종료" 와 같다(남은 대기열은 다음 시작 때 복구 — #1c).
- 자동 시작 설정을 `start` 가 바꾸기 — 기각(라운드 2 Q4 의 다른 안). 트레이 모드로 떠 있으면 `start` 가 모드를 바꾼다.

## 성공 기준

- A1: 꺼진 상태에서 `start` 를 부르면 트레이 아이콘 없이 앱이 뜨고, 받을 준비가 된 뒤 종료 코드 0 으로 끝난다. 브라우저는 열리지 않는다.
- A2: 트레이 없는 모드로 떠 있을 때 `start` 를 부르면 새 프로세스 · 화면 없이 0 으로 끝난다. 트레이 모드로 떠 있을 때 부르면 트레이가 사라지고 트레이 없는
  모드로 다시 뜬 뒤 0 으로 끝난다.
- A3: 부모 프로세스(기본 = 부른 프로세스, `--parent <PID>` 지정)가 끝나면 트레이 없는 모드의 앱 · 감시가 정상 종료한다.
- A4: `open` 은 떠 있으면 화면을 열고, 꺼져 있으면 트레이 없이 띄운 뒤 연다.
- A5: `stop` 을 부르면 (두 모드 모두) 앱 · 감시가 모두 끝난 뒤 0 으로 끝난다(꺼져 있으면 바로 0). 10초 안에 끝나지 않으면 0 이 아닌 코드와 사유.
  오류 트레이도 `stop` 으로 꺼진다.
- A6: 인자 없는 실행 · `start` · `open` 을 동시에 · 거듭 불러도 앱 · 감시 프로세스는 각각 하나, 트레이는 많아야 하나다. 오류 트레이도 거듭 실행으로 늘지 않는다.
- A7: 트레이 없는 모드에서 시작에 실패하면 `start` · `open` 이 0 이 아닌 코드와 사유를 낸다(트레이 없음).
- A8: 인자 없는 실행 · 자동 시작은 트레이 모드, 두 번째 실행은 화면 열기(회귀 없음). 기존 CLI(`peers` · `ask` · `wait` · `status` · `history`) 회귀 없음.
- A9: 검증 명령(`cargo test --workspace` · clippy · `check_gates` · `check_ddd_docs` · `check_readme`) 통과.

## 결정

- 명령 = `start` · `open` · `stop`. 기각: `open` · `quit`(트레이 메뉴 이름). `open` 은 라운드 1 에서 뺐다가 트레이 없는 모드 지시로 라운드 2 에서 넣었다.
- `start` = 항상 트레이 없는 모드 · 화면 안 엶 · 이미 (트레이 없이) 떠 있으면 아무것도 안 함. 기각: `start --no-tray` 플래그 · 설정 "트레이 표시" 고정.
- `stop` = 끝날 때까지 기다림(최대 10초) — 실행 파일 교체 전에 부를 수 있게. 기각: 요청만 보내고 바로 돌아옴.
- 수명 = 부모와 함께 끝남(감시는 부모가 살아 있는 동안 비정상 종료를 다시 띄움). 기각: 독립 · `stop` 으로만 끔.
- 부모 = 기본 자동(부른 프로세스) + `--parent <PID>`. 기각: `--parent` 필수 · 자동만.
- 이미 트레이 모드 = 트레이 없는 모드로 바꿈(재시작). 기각: 그대로 둠 · 자동 시작 설정까지 끔.
- 중복 범위 = 빈틈 전부(오류 트레이 · 동시 실행의 감시 프로세스 · `start` · `open` 동시 호출). 기각: `start` 만.
- 인자 없는 두 번째 실행 = 화면 열기(그대로). 기각: 아무것도 안 함.
