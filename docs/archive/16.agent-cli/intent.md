# intent — 16.agent-cli

승인: 2026-10-12

## 왜

사용자의 AI 에이전트(예: 로컬 Claude Code)가 웹UI 를 거치지 않고 등록된 상대(피어)에게 직접 문의할 수 있어야 한다. 사용자 원문
(2026-10-12 대화): "coworkAgent 에 등록된 사용자에 대한 cli 기능 제공. 왜냐하면 사용자의 ai agent 가 직접 호출할 수 있어야하며,
이 경우 대화이력에는 agent 가 실행한 이력으로 관리. 동일하게 타임라인, 대화내용을 확인 가능하여야함." — 출처:
[feedback/2026-10-12-improve-coworker.md](../../feedback/2026-10-12-improve-coworker.md). 닿는 masterPlan 항목: D14(실행 파라미터 ·
단일 인스턴스) · S8(다른 툴이 부르는 실행 파라미터 — Phase 3 을 이 부분만 앞당긴다) · D23(발화자) · D24(실행 시간 제한 30분) ·
D26(대화 화면 A + 타임라인 C) · D31(받는 쪽 문의 응답 전용). 이 Task 가 없으면 AI 에이전트는 사람이 웹UI 에 옮겨 적어야만 상대에게 묻는다.

## 범위

- 같은 실행 파일 `coworkAgent` 의 CLI 하위 명령 — 주 인스턴스가 떠 있으면 그 로컬 API 를 부른다(`handoff.rs` 의
  `InstanceInfo` 포트 · bearer 토큰 경로 재사용).
- 피어 목록 조회 — 등록된 사용자 · 연결 상태.
- 상대 에이전트에게 질문 보내고 답 받기 — 같은 대화 이어 쓰기(대화 ID) 포함.
- 상대 사람에게 글 보내기(실행 없이 남기는 글, D23 "사람에게").
- 대화 목록 · 이력(타임라인) 조회.
- 기본은 답이 올 때까지 대기(실행 시간 제한 30분, D24) · 텍스트 출력, 즉시 반환 옵션과 `--json` 옵션.
- 이력: 새 발화자 "내 AI 에이전트(CLI)" — 내 PC · 상대 PC 양쪽 이력 · 웹UI 대화 화면 · 타임라인에 사람 글과 구분해 표시
  (피어 프로토콜 `author` 값 추가).

## 제외

- `coworkAgent chat [--peer <사용자ID>]`(대화 UI 로 바로 진입, D14) — S8 Phase 3 그대로.
- 웹UI 디자인 개편 — [15.ux-refresh](../15.ux-refresh/intent.md). 16 은 현 화면에 발화자 구분만 더하고 15 가 새 디자인에 포함한다.
- 원격 실행 권한 확대 — 받는 쪽은 D31(문의 응답 전용 · 읽기 전용 도구) 그대로.
- 주 인스턴스 없이 CLI 단독 동작 · CLI 가 앱을 대신 띄우기 — 실행 중이 아니면 오류로 끝낸다(결정).

## 성공 기준

- A1: `peers` 로 피어 목록을 조회하면 등록된 사용자 · 연결 상태가 텍스트로, `--json` 이면 JSON 으로 나온다.
- A2: `ask` 로 상대 에이전트에게 질문하면 답이 올 때까지 기다려 stdout 으로 돌려주고, 대화 ID 를 주면 같은 대화를 이어 쓴다.
  즉시 반환 옵션이면 대화 ID 만 돌려준다. 실패 · 시간 초과는 0 이 아닌 종료 코드와 사유를 낸다.
- A3: `say` 로 상대 사람에게 실행 없는 글을 남길 수 있다.
- A4: `history` 로 대화 목록과 한 대화의 이력(타임라인)을 조회한다.
- A5: CLI 로 나간 글은 내 PC · 상대 PC 이력에 발화자 "내 AI 에이전트(CLI)" 로 저장되고 웹UI 대화 화면 · 타임라인에서 사람 글과 구분돼 보인다.
- A6: 파이프로 CLI 를 부르는 AI 에이전트(릴리스 빌드, 콘솔 없는 Windows 서브시스템)가 stdout · 종료 코드를 받는다.
- A7: coworkAgent 가 실행 중이 아니면 CLI 는 "coworkAgent 가 실행 중이 아니다" 사유와 0 이 아닌 종료 코드로 끝난다.
- A8: 로컬 API 는 잠금 파일 bearer 토큰 없이는 CLI 요청을 거부한다(웹UI 와 같은 신뢰 경계).

- **범위** — 피어 목록 · 질문 보내고 답 받기(이어 쓰기 포함) · 대화 목록 · 이력 조회 · 상대 사람에게 글 보내기(4개 모두 선택).
- **응답 방식** — 답까지 대기 + `--json` 옵션 · 즉시 반환 옵션. 기각안: 즉시 반환 + 나중에 조회(JSON 기본).
- **이력 표시** — 양쪽 PC 에 "내 AI 에이전트(CLI)" 구분 표시, 피어 프로토콜 `author` 값 추가. 기각안: 내 PC 에만 · CLI 호출마다 웹UI 확인.
- **보안(위험 수용)** — 같은 OS 사용자의 아무 로컬 프로세스나 CLI 로 상대에게 보낼 수 있다(잠금 파일 토큰 = 웹UI 와 같은 신뢰 경계).
  보완: CLI 호출은 전부 이력에 남는다.

확인된 사실:

- CLI 인자 처리는 아직 없다 — `crates/app/src/main.rs` 는 두 번째 실행을 `hand_off` 로 넘길 뿐이다.
- 두 번째 실행은 잠금 파일의 `InstanceInfo`(포트 · 토큰)로 `POST /api/open` 을 부른다(`handoff.rs`).
- 발화자는 `crates/core/src/chat.rs` `Author::Human` · `Agent`(원격 실행 에이전트), 피어 프로토콜 `proto.rs` 에 `author` 문자열("human" · "agent").
- 릴리스 빌드는 `windows_subsystem = "windows"` — 콘솔이 없다. 파이프 stdout 동작은 plan 에서 실측(A6).

라운드 2(2026-10-12, 사용자 답):

- **명령 literal** — 하위 명령 4개(기각안: `coworkAgent cli <명령>` 그룹):

  ```text
  coworkAgent peers [--json]
  coworkAgent ask <상대> "<질문>" [--agent <이름>] [--conv <대화ID>] [--no-wait] [--json]
  coworkAgent say <상대> "<글>" [--conv <대화ID>] [--json]
  coworkAgent history [<상대>] [--conv <대화ID>] [--json]
  ```

  `<상대>` = 피어 표시 이름 또는 지문 앞자리, 겹치면 오류. D14 TODO("`--peer` 값이 사용자ID 인지 `사용자/에이전트명`") 중 CLI 쪽은 이 결정으로 닫는다 — 종결 시 D14 환류.
- **앱 미실행 시** — 오류로 끝낸다(기각안: 주 인스턴스를 띄우고 진행).
