## 범위

- 에이전트 프로필에 **"상위 한단계 탐색 허용"** 옵션(기본 끔) — 등록 화면 · 에이전트 상세(수정) 체크박스, API `parent_read`.
- 켜면 실행(`claude -p`)이 에이전트 폴더의 **바로 위 폴더 하나**를 `--add-dir` 로 더 연다 — 그 위는 열지 않는다(한 단계 고정).
- 바로 위가 드라이브 루트 · 사용자 홈이거나 데이터 루트를 품는 곳(1a A7 규칙)이면 켜도 열지 않는다(폴더만 — 로그 한 줄, 상세에 "열지 않음").
- 매뉴얼 · PRODUCT · masterPlan(D21 · D22) 반영.

- A2: 실제 `claude` 를 제품 인자로 돌려 — 켜면 바로 위 폴더 파일을 읽고, 끄면 거부, 켜도 두 단계 위는 거부(실측).
- A3: 등록 화면 · 에이전트 상세에 "상위 한단계 탐색 허용" 체크박스가 있고 저장 · 다시 읽기에 그 값이 남는다. 켰을 때 상세에 실제 여는 위 폴더(또는 "열지 않음")가 보인다(시험 · 실제 화면).

- A5: 회귀 없음 — PROJECT.md 검증 명령 PASS, 매뉴얼 · PRODUCT 반영(검사).

## 결정

1. 상위 범위 = **바로 위 한 단계 고정**(선생님 "b"). 수단 = `--add-dir <위 폴더>` — `--settings` `additionalDirectories` 도 되지만 인자 하나로 끝나고 D22 인자 목록에 그대로 드러난다.
2. 켜고 끄기 = **에이전트별 체크박스**(선생님 지시) — 라벨 literal "상위 한단계 탐색 허용", 기본 끔(지금까지와 같은 범위 — 넓히는 쪽은 사람이 고른다).
3. 막는 위 = 드라이브 루트 · 사용자 홈(질문 답) + 데이터 루트를 품는 곳 · 네트워크 경로(1a A7 규칙 재사용 — 예: `%LOCALAPPDATA%\x` 의 위는 키 · DB 가 든 데이터 루트를 품는다).
   판단은 **실행마다**(등록 뒤 링크가 바뀌어도) — 막히면 폴더만으로 실행(실패로 돌리지 않는다), 로그 한 줄 · 상세 표시.
4. 옵션을 바꾸면 폴더를 바꾼 것처럼 새 세대 · 세션 비움 — 끈 뒤에도 위 폴더 내용이 든 세션 · 압축 요약을 잇지 않게.
5. 켜면 시스템 프롬프트에 `[읽기 범위]` 한 줄(이 폴더 + 바로 위, 그 위는 읽을 수 없다) — 모델이 위 폴더를 찾아 읽을 수 있게. 가드(`GUARD_PROMPT`) 문구는 그대로.
6. Task 번호 = `05-2`(Phase 1 버퍼 `10~19` · 오버플로 `1a~1z` 소진 — 원격 실행 가드 계열 `05.inquiry-guard` 의 하위 트랙, 구현자 해석).
