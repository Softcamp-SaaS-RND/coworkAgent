# intent — 15.ux-refresh

승인: 2026-10-12

## 왜

프로토타입(Phase 1)을 써 본 사용자의 개선 요청 — 화면이 텍스트 나열이라 키·값 · 편집·읽기 구분이 안 되고, 톤 · 폰트가
제각각이며, 초대 · 허용 단계가 길고, 연결 · 에이전트 목록이 많아지면 찾기 어렵고, 등록한 항목을 고칠 수 없다(삭제만).
메인 화면에서 사람을 골라도 그 사람과의 대화가 바로 보이지 않는다. 출처: [feedback/2026-10-12-improve-coworker.md](../../feedback/2026-10-12-improve-coworker.md)
(사용자 작성 원문 + 대화 추가 1건 — favicon). 닿는 masterPlan 항목: S4(슬랙형 UI) · D26(시안 A 기본 + C 타임라인) ·
D8(최초 연결 시 양측 승인) · D21(에이전트 프로필) · D22 · D31(읽기 전용 도구 고정) · D16(`claude -p` 연동) · D29(알림 설정).
이 Task 가 없으면 연결 · 에이전트가 늘어날수록 웹UI 를 쓰기 어렵고, 잘못 등록한 항목은 지우고 다시 만들어야 한다.

## 범위

웹UI 공통 디자인(시안 5개 결정) · favicon · 초대 단계 축소 · 연결/에이전트 목록 필터 · 편집 · 모델 옵션 · 메인 화면 메시지 목록.
원문 항목을 화면별로 옮겼다(문구는 원문 그대로 — 분할 · 순서는 미해소 1 · 2).

- **공통 UI**
  - 표 또는 컨트롤로 키 · 값을 명확히 구분, 편집 가능한 정보와 읽기 전용 정보 표시.
  - 폰트 · 크기 일정하게 유지. 전체 톤 · 매너 일관.
  - 설정 항목 트리뷰 — 설정 가능한 전체 목록 시인성.
  - 화면 내용이 markdown · html 이면 뷰어로 표시, 편집 · 읽기 모드 전환 버튼.
  - 현재 등록 · 작성된 데이터 기준 디자인 시안 5개 → 아티팩트 게시 → 사용자 결정.
  - browser favicon 을 에이전트 아이콘(`crates/app/assets/coworkAgent.ico` — 실행 파일 · 트레이와 같은 그림)으로. 지금은
    favicon 을 내보내지 않는다(`index.html` 에 `<link rel="icon">` 없음).
- **설정 화면**
  - 초대 생성: 생성된 초대 메시지로 상대가 초대 수락하면 추가 승인 없이 바로 등록.
  - 초대 수락: 붙여넣기 설명을 '초대 생성'에서 생성된 메시지 입력으로 변경, "메신저로 받은" 표시 제거
    (현재 `index.html` "메신저로 받은 coworkAgent 페어링 초대 메시지를 통째로 붙여 넣으세요" 등).
  - 연결 목록을 아코디언 컨트롤로, 등록 사용자가 많으면 그룹화할 수 있게 필터.
  - 이미 등록된 사용자에 대한 도구 변경 기능(의미는 미해소 4).
  - `claude -p` 헤드리스 기본 모델 sonnet, effort high — 설정 옵션 제공.
  - (대화 추가 2026-10-12) 기본 설정 외에 등록한 상대방별로 model · effort 조정.
- **내 에이전트**
  - 공유된 목록을 먼저 출력, 그룹화 · 필터 · 검색(경로가 많이 등록될 수 있음).
  - 등록된 경로 · 도구 편집(지금은 삭제만).
  - 추가 지시에 대한 구체적인 사용 예제 가이드.
- **알림**
  - 텍스트와 컨트롤 크기 불일치 수정.
  - 문구 "새 자동 왕복 대화의 상한 기본값"(`index.html` `relay_cap_default` 라벨) → 대화 턴에 대한 상한 기본값으로 변경.
- **메인 화면**
  - '나' · 등록 사용자 클릭 시 해당 사용자와의 대화 내용 표시.
  - '나' 선택 시 나에게 들어온 메시지 목록 + 필터 · 검색.
  - 나머지(등록 사용자)는 내가 보낸 메시지 목록으로 출력.

## 성공 기준

- A1: 디자인 시안 5개(실제 데이터의 구조 · 분량 유지, 이름 · IP · 지문 · 경로 익명화)를 아티팩트로 게시하고 사용자가 1개를 고른 결정이 이 문서 `## 결정` 에 기록된다.
- A2: 고른 시안 기준으로 전 화면의 폰트 · 크기 · 색이 공통 토큰(CSS 변수) 하나에서 나오고, 키 · 값과 편집 · 읽기 전용이 시각적으로 구분된다.
- A3: 설정 항목이 트리뷰로 전부 보인다.
- A4: markdown · html 내용이 뷰어로 보이고, 대화 머리글의 "원문 보기" 버튼 하나로 대화 · 타임라인의 모든 본문을 원문 ↔ 뷰어로 바꾼다.
  입력칸은 늘 편집 상태(편집 / 미리보기 버튼 없음)(개정 2026-10-12 라운드 4).
- A5: 웹UI 탭 favicon 이 `coworkAgent.ico` 와 같은 그림이다.
- A6: 초대 생성 측은 그 초대(5분 창 · 1회용 코드)로 들어온 요청을 추가 승인 없이 등록하고, 등록 즉시 알림(D29)을 띄우며 연결 목록에서 바로 삭제할 수 있다.
- A7: 초대 수락 측 안내 문구가 '초대 생성'에서 생성된 메시지 입력 기준이고 "메신저로 받은" 표시가 없다.
- A8: 연결 목록이 아코디언으로 보이고 그룹 필터가 있으며, 목록에서 내 에이전트 프로필의 도구를 D31 읽기 전용 목록 안에서 편집할 수 있다.
- A9: `claude -p` 실행이 기본 `--model sonnet` · `--effort high` 를 붙이고, 설정의 기본값과 등록한 상대방별 덮어쓰기(비우면 기본값)를 바꾸면
  그 상대 요청의 다음 실행에 반영된다(개정 2026-10-12 — 사용자 지시 "model, effort 는 기본 설정외에 등록한 상대방별로 조정 가능하도록 옵션 제공.").
- A10: 내 에이전트 — 공유 목록 우선 출력 · 그룹 · 필터 · 검색 · 등록된 경로 · 도구 편집 · 추가 지시 사용 예제 가이드.
- A11: 알림 화면 텍스트 · 컨트롤 크기가 같고, `relay_cap_default` 라벨이 대화 턴에 대한 상한 기본값 문구다.
- A12: 메인 화면 — 타일(레일의 '나' · 등록 사용자)을 누르면 사이드바에 그 타일의 대화 목록('나' = 전체)이 나오고, 메인은 대화를 고를 때까지
  안내, 고르면 그 대화(D26) — 대화 화면 위에 내가 보낸 메시지 목록 탭. '나' 에게 들어온 메시지 목록(필터 · 검색) · 그 사용자와 주고받은 글 목록은
  사이드바 머리의 링크. 설정은 대화 목록 없이 전체 폭, 대화 목록 폭은 끌어서 조절하고 이 PC 설정에 저장(개정 2026-10-12 라운드 4 · 5).
- A13: 설정에서 화면 테마를 다크(기본) · 라이트로 고르고, 고른 값이 이 PC 설정에 저장돼 다시 열어도 유지된다(개정 2026-10-12, 기본 다크는 라운드 4).
- A14: 새 글은 모두 대화 에이전트에게 실행 요청이다 — 웹UI 에 대상 선택이 없고, CLI `say` 는 없으며(모르는 명령 2), 로컬 API `to: "human"` 은 400.
  기존 이력의 사람 글(실행 없음)은 그대로 보인다(개정 2026-10-12).
- A15: 대화 목록 · 머리글의 방향 표시가 화살표(→ ←) 대신 "보냄" · "받음" 태그다(개정 2026-10-12).
- A16: 새 대화에 '제목' 칸(비우면 첫 메시지 앞부분)이 있고, 대화 머리글 제목 옆 편집 버튼으로 제목을 고친다 — 제목은 이 PC 에만 저장하고
  상대에 보내지 않는다. 사이드바 검색은 "제목 검색"(제목으로만 거름)(개정 2026-10-12 라운드 5).
- A17: 타일을 고른 뒤 사이드바 머리의 편집 버튼으로 그 타일('나' 포함)의 표시 이름(별칭)과 아이콘을 바꾼다 — 표시 이름은 타일 글자(앞 두 글자) ·
  사이드바 머리 · 대화 목록 · 메시지의 상대 이름에 쓰이고(설정 연결 목록에는 원래 이름도), 아이콘은 타일 글자 대신 보인다. 이 PC 에만 저장
  (개정 2026-10-12 라운드 5).
- A18: 트레이 메뉴(정상 모드)는 "열기" · "종료" 만이다 — "내 정보 보기" 삭제(masterPlan S4 개정, 개정 2026-10-12 라운드 5).
