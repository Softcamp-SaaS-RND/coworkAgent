# intent — 10.slack-ui

승인: 2026-10-11 (자동 진행 위임 + 확인 답 4건)

## 왜

지금 웹UI 는 한 열에 상태 · 내 정보 · 피어 · 에이전트 · 대화를 늘어놓은 관리 페이지다. 제품은 "슬랙과 같은 디자인"(S4)의 대화
도구이고, 화면 결정은 시안 **A(클래식 3단 메신저) 기본 + C(요청 타임라인) 화면을 여는 조합**(D26)이다. 이 Task 가 없으면 Phase 1 의
양쪽 사람 발화(D18 · D23) · 자동 왕복(D24)을 올릴 화면이 없다. 화면 로직의 자동 테스트 기반도 없다 — 원장의 "JS 테스트 기반 도입
시(Phase 1 UI)" 4건(#00 R1-F4 · #02 R2-F3 · #03 R1-F4F5 · #04 R2-F3)이 이 조건을 기다린다.
— 출처: masterPlan S4 · D26 · D10 · D19 · [overview/ui-mockups.md](../../overview/ui-mockups.md) 시안 A · C, 확인 답(2026-10-11).

## 범위

- 웹UI 를 시안 A 3단으로 다시 짠다: **PC 레일**(내 PC + 페어링된 PC, 고르면 그 상대의 대화만 · 레일 `+` = 초대 붙여넣기 · 레일
  하단 **설정**) · **사이드바**(내 에이전트 · 대화 → 보낸 / ← 받은 · 연결 가능한 사용자) · **대화 영역**(머리글 · 메시지 · 입력창).
- **설정 화면**(레일 하단 → 메인 영역): 내 정보 · 피어(초대 · 직접 추가 · 승인 · 삭제 · 연결 확인) · 내 에이전트 등록 · 알림 설정 —
  지금 기능 그대로 옮긴다. 트레이 "내 정보 보기"(`#me`)는 이 화면의 내 정보 칸을 연다.
- **새 대화**: 사이드바 "대화" 의 `+` → 상대 · 상대 에이전트 · 첫 메시지.
- **C 타임라인 화면**: 대화 머리글에서 연다 — 요청마다 요청 → 실행(턴 · 시간) → 응답 단계와 시각 · 상태.
- 실행 정보 저장: `claude` JSON 의 `num_turns` · `duration_ms` 를 답에 싣고(`reply` 에 선택 필드) 양쪽이 저장, 답이 어느 요청의 답인지
  (`reply_to`) 저장 — 스키마 5. 대화 목록 API 에 제목(첫 메시지 앞부분) · 마지막 상태 · 마지막 시각, 메시지 API 에 시각 · 실행 정보.
- JS 테스트 기반: 화면 로직(상태 문구 · 대화 제목 · 상대별 거르기 · 타임라인 묶기 · 늦은 응답 폐기)을 순수 함수 ES 모듈로 빼고
  `node --test` 로 TDD. 검증 명령 표에 행 추가.

## 제외

- 양쪽 사람 발화(받은 대화에 사람이 쓰기 · 사람끼리) — `11.two-sided-chat`(D18 · D23).
- 자동 왕복 · "자동 왕복 n/10" · 멈춤 — `12.auto-relay`(D24).
- 도구별 사용 횟수(시안의 "도구 Read 6") — `claude` JSON 출력에 없다.
- 이력 검색(시안 C 의 검색 칸) · "터미널에서 열기" — 후속(필요 시 masterPlan 개정).
- 실제 브라우저 화면 확인 — `19.prototype-acceptance`(D28). 브라우저 자동화 도구는 들이지 않는다.
- 연결 가능 목록의 자동 발견(S5 · mDNS) — Phase 2. 여기 "연결 가능한 사용자" 는 피어 표.

## 성공 기준

- A1: 웹UI 첫 화면이 시안 A 3단(PC 레일 · 사이드바 · 대화 영역)이고, 지금의 관리 기능(내 정보 · 피어 · 에이전트 등록 · 알림 설정)은
  모두 레일 하단 "설정" 화면에서 쓸 수 있다. 트레이 "내 정보 보기" 는 그 화면의 내 정보를 연다.
- A2: 레일에서 PC 를 고르면 사이드바 대화가 그 상대의 것만 남고, 새 대화 · 이어 쓰기 · 대화 전환이 된다. 늦게 온 다른 대화의 응답은
  화면에 그려지지 않는다.
- A3: 대화 머리글에서 C 타임라인을 열면 요청마다 요청 → 실행(턴 · 시간) → 응답이 시각 · 상태와 함께 보인다(양쪽 PC 모두).
- A4: 답에 실행 정보(`num_turns` · `duration_ms`)와 원 요청 대응이 실리고 양쪽 DB 에 남는다(스키마 5). 실행 정보가 없는 출력 · 이전
  버전 상대도 받는다.
- A5: 화면 로직의 자동 테스트가 `node --test` 로 돌고 루트 `PROJECT.md` 검증 명령에 들어간다.
- A6: 원격에서 온 이름 · 본문은 여전히 텍스트로만 그린다(`innerHTML` 없음).
- A7: 루트 `PROJECT.md` 검증 명령(테스트 · 경고 0 · 의존 경계 · JS 테스트)이 통과한다.

## 결정

- 분할: Phase 1 = `10.slack-ui` → `11.two-sided-chat` → `12.auto-relay` → `19.prototype-acceptance` — 확인 답 "4 Task 순차".
  기각안: UI 와 발화를 한 Task.
- 관리 화면: 레일 하단 "설정" → 메인 영역 — 확인 답. 기각안: 모달 · 사이드바 펼침.
- JS 테스트: `node --test`(Node 내장, 개발 PC 에만 필요 · 제품 의존 없음 · 빌드 단계 없음 — D10 유지) — 확인 답. 기각안: 도입 안 함.
  테스트 대상은 DOM 없는 순수 함수 모듈 — 화면 조립(DOM)은 수동(D28).
- 타임라인: 있는 데이터 + 턴 · 시간(스키마 5) — 확인 답. 기각안: 있는 데이터만.
- PC 레일 거르기 · 레일 `+` = 초대 붙여넣기 · 대화 제목 = 첫 사람 메시지 앞부분 — 권장안(자동 진행 위임).
- 받은 대화(←)의 입력창은 이 Task 에서 막아 둔다(안내 문구) — 사람 발화는 11.
