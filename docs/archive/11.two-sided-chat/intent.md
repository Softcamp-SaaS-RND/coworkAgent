# intent — 11.two-sided-chat

승인: 2026-10-11 (자동 진행 위임 + 확인 답 3건)

## 왜

D18(사람은 대화에 직접 작성, 발신자 '사람' 표시) · D23(대화 = 두 PC 사이, 발화자 = 양쪽 사람 + 에이전트)이 아직 없다 — 지금은 보낸 쪽
사람만 쓰고 모든 글이 에이전트 실행이 되며, 받은 쪽 사람은 입력창이 막혀 있다(10 의 결정). — 출처: masterPlan D18 · D23 · S1, 확인 답
(2026-10-11) "글마다 고름" · "글마다 대상 고름 (권장)" · "다음 실행에 앞붙임 (권장)".

## 범위

- 양쪽 사람 모두 대화에 쓴다. 글마다 대상을 고른다 — **에이전트에게**(대화의 에이전트가 실행 · 답) / **사람에게**(실행 없음, 상대 사람과
  양쪽 이력에만). 기본은 에이전트에게.
  - 보낸 쪽(A, `out`)의 "에이전트에게" = 지금처럼 상대 PC 에이전트 실행.
  - 받은 쪽(B, `in`)의 "에이전트에게" = 이 PC 의 그 대화 에이전트가 실행, 사람 글과 답은 A 이력에도 남는다.
- 양쪽 이력이 같은 대화를 같은 순서 · 같은 발화자로 보여 준다 — 글마다 "내가 쓴 것인가"(`mine`) · "실행 요청인가"(`exec`) 를 남긴다(스키마 6).
- 에이전트 실행 때, 지난 실행 요청 뒤 그 사이 오간 사람 글을 입력 앞에 붙여 넘긴다(맥락).
- 받은 사람 글 · 미러된 답은 알림(S9) 이벤트로.
- 웹UI: 양쪽 입력창 + 대상 선택, 발화자 표시(나 · 상대 사람 · 에이전트).

## 제외

- 에이전트 간 자동 왕복 — `12.auto-relay`(D24).
- 3 PC 이상 다자 대화(D23 기각안).
- 미러 실패 재전송(상대가 꺼져 있을 때) — Phase 2(D7).
- 실화면 · 실제 `claude -p` 확인 — `19.prototype-acceptance`(D28).

## 성공 기준

- A1: 받은 쪽 사람이 받은 대화에 "사람에게" 로 쓰면 실행 없이 양쪽 이력에 상대 사람 글로 남고, 보낸 쪽 사람의 "사람에게" 도 마찬가지다.
- A2: 받은 쪽 사람이 "에이전트에게" 로 쓰면 그 PC 의 대화 에이전트가 실행하고, 사람 글과 답이 양쪽 이력에 같은 순서로 남는다.
- A3: 에이전트 실행 입력에 지난 실행 요청 뒤의 사람 글이 발화자와 함께 앞에 붙는다(표준 입력, 가드 규칙 그대로).
- A4: 원격에서 온 미러 글은 그 상대 소유 대화에만 붙고(다른 상대 · 없는 대화 · 미페어링 거부), 같은 글 재전송은 한 번만 남는다.
  에이전트 답 미러는 그 상대가 쓴 사람 글에 대한 답일 때만.
- A5: 이전 이력(스키마 5)은 `mine` · `exec` 가 방향으로 채워져 그대로 보인다.
- A6: 루트 `PROJECT.md` 검증 명령이 통과한다.

## 결정

- 대상 선택: 양쪽 모두 글마다 "에이전트에게 / 사람에게", 기본 에이전트 — 확인 답 2건.
- 사람 글 맥락: 다음 실행 입력 앞에 붙임 — 확인 답.
- 프로토콜: 실행 요청은 지금의 `message`, 실행 없는 글 · 받은 쪽 미러는 새 요청 `post`(사람 글 · 에이전트 답) — 권장안(자동 진행 위임).
  기각안: `message` 에 플래그만 더하기(받은 쪽 → 보낸 쪽 방향이 없음).
- 받은 쪽 실행 요청의 답은 `post`(에이전트, `reply_to` = 그 사람 글 uuid)로 미러 — 권장안.
- 미러 실패는 로그 + 웹UI 안내까지(재전송은 Phase 2) — 권장안.
