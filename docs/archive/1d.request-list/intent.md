# intent — 1d.request-list

승인: 2026-10-13 (라운드 2 + 사용자 답 "승인.")

## 왜

에이전트 설정이 쓰기 어렵고, 고치기 · 만들기 같은 일은 맡길 길이 없다 — 모델은 아무 글이나 넣는 입력칸이고, 탐색 도구(Read · Grep · Glob · LS)는
빼면 질의가 처리되지 않는데도 체크 항목으로 나와 있다. D31 은 원격 실행을 읽기 전용 문의 응답으로 고정했으므로 "이것 좀 고쳐 달라" 는
지금 받을 곳이 없다. — 출처: 대화(2026-10-13) 사용자 원문 "사용가능한 모델은 opus, sonnet,hiku 등 claude에서 제공하는 모델 드롭다운
리스트로 제공 / 사용 가능한도구 중 검색도구는 기본 사용이므로 체크박스 항목에서 제거. 읽기 권한에서의 질의성 요청은 기본 도구가 있어야
처리가능함 / 도구를 선택지에서 질의(탐색)과 요청으로 구분 / 요청의 경우 프롬프트의 내용으로 사용자에게 요청 목록으로 등록하며, 사용자는
요청자의 요청내용을 롹인하고 수용,반려 등의 결과 피드백을 한다.실시간으로 처리하지 못하므로 목록 관리를 통해 제어한다" · masterPlan
D21 · D22 · D31.

## 범위

- 모델 선택을 드롭다운으로 — `opus` · `sonnet` · `haiku`(전역 설정 · 상대별 덮어쓰기 둘 다, 상대별은 "기본값" 항목 포함).
- 탐색 도구(읽기 전용 5개)는 모든 프로필 실행에 늘 들어가고, 프로필의 도구 체크 칸은 없앤다.
- 질의 · 요청 구분은 입력창 선택(#18) 그대로 — **질의** = 에이전트가 답, **요청** = 실행하지 않고 받는 PC 의 **요청 목록**에 등록 → 받은
  사람이 수용 · 반려 · 완료로 답(한 줄 메모) → 요청자에게 결과가 간다.
- 왼쪽 메뉴 '요청' 화면(받은 요청 · 보낸 요청 · 상태 거르기).

## 제외

- 다자(3 PC 이상) 요청 · 담당자 지정 — D23 기각안.
- 실시간 처리 — 목록으로 다룬다(사용자 원문).
- 수용한 요청을 에이전트가 쓰기 도구로 처리 — 라운드 1 기각(D31 유지).
- 요청자의 요청 취소 · 고치기, CLI(`coworkAgent ask`)로 요청 보내기 — 필요해지면 다음 Task.
- 웹 도구(`WebSearch` · `WebFetch`).

## 성공 기준

- A1: 모델은 드롭다운에서만 고르고(`opus` · `sonnet` · `haiku`, 상대별은 "기본값" 포함), 목록 밖 값은 저장 · 실행 거부, 이미 저장된 목록 밖
  값은 마이그레이션으로 기본값이 된다.
- A2: 프로필 화면 · API 에 도구 칸이 없고, 어떤 프로필이든 실행 인자 `--tools` · `--allowedTools` 가 읽기 전용 5개다.
- A3: 요청 글은 받는 PC 에이전트를 실행하지 않고(대기열 · 실행 기록 없음) 받는 PC 요청 목록에 '대기' 로 남는다. 집중 중에도 받는다.
- A4: 받은 사람만 상태를 대기 → 수용 · 반려, 수용 → 완료로 바꾸고(메모 한 줄), 바뀐 상태 · 메모가 요청자 쪽 대화 · 요청 목록에 보인다 —
  요청자가 꺼져 있어도 outbox 로 나중에 간다.
- A5: 왼쪽 메뉴 '요청' 화면이 받은 요청 · 보낸 요청을 상태로 걸러 보여 주고, 항목에서 그 대화로 간다. '내 활동' 의 요청 거르기는 없다.
- A6: 이전 이력의 완료 표시된 요청은 '완료', 나머지 요청은 '대기' 로 보인다.
- A7: 루트 `PROJECT.md` 검증 명령이 통과한다.

## 결정

라운드 1(2026-10-13):

- **수용 = 사람이 처리** — 확인 답 "사람이 처리 (Recommended)". 받는 PC 사람이 직접 처리하고 결과를 적어 보낸다. 원격 실행은 계속 읽기
  전용(D31 유지). 기각안: 수용 시 쓰기 도구로 에이전트 실행 · 수용 때마다 선택(둘 다 D31 개정 · 상대 글이 쓰기 권한 실행 입력이 됨).
- **요청 = 보내는 사람이 고름** — 확인 답 "보내는 사람이 고름 (Recommended)". #18 의 입력창 질의 | 요청 선택을 그대로 쓴다. 기각안: 에이전트
  판정(LLM 오판) · 도구로 판정.
- **탐색 도구 전부 늘 제공 · 체크 항목 없음** — 답 원문 "없음. 모든 탐색 도구는 제공함". D31 읽기 전용 목록 5개(`Read` · `Grep` · `Glob` ·
  `LS` · `NotebookRead`)를 모든 프로필 실행에 늘 넣는다(판단 — "모든 탐색 도구" = 이 5개, 웹 도구 `WebSearch` · `WebFetch` 는 권장안 밖 선택지로
  보여 드렸고 고르지 않으셨으므로 넣지 않는다). 기각안: `NotebookRead` 만 체크 · 웹 도구 추가.
- **상태 = 대기 · 수용 · 반려 · 완료** — 확인 답 "대기·수용·반려·완료 (Recommended)". 대기 → 수용 · 반려, 수용 → 완료. 단계마다 한 줄 메모,
  요청자 대화에 결과 글 + 양쪽 요청 목록에 상태.
- **#18 과의 충돌(편차 기록)** — #18 결정 "실행은 종류와 무관"(요청도 에이전트가 답함) · "받은 쪽만 완료 표시"(완료 1단계) 를 이 Task 가 바꾼다
  → 라운드 2 에서 개정으로 확정.

라운드 2(2026-10-13):

- **요청 = 실행 없음 · 목록만** — 확인 답 "실행 없음 · 목록만 (Recommended)". S1 #18 보강 개정: 요청 글은 받는 PC 에이전트를 실행하지 않고 요청
  목록에만 등록, 질의만 에이전트가 답한다. #18 의 "받은 쪽만 완료 표시"(`done_at`) 는 상태 4단계로 대체 — 이미 완료 표시된 요청은 완료로 옮긴다.
  기각안: 에이전트 답 + 목록.
- **요청 목록 = 왼쪽 메뉴 '요청' 화면** — 확인 답 "왼쪽 메뉴 '요청' 화면 (Recommended)". 받은 요청 · 보낸 요청 탭, 상태 거르기, 항목에서 대화로
  이동. 17 '내 활동' 의 요청 거르기는 뺀다. 기각안: 내 활동 거르기 확장.
- **도구 칸 = 화면에서 빼기** — 확인 답 "화면에서 빼기 (Recommended)". 프로필 등록 · 편집 · 연결 목록의 도구 체크를 없애고 "탐색 도구(읽기 전용)
  항상 사용" 안내 한 줄. API 의 `tools` 입력도 없앤다. 기각안: 비활성 체크 표시.

자동 진행 위임(masterPlan "자동 진행 위임")으로 정한 것:

- **모델 목록 = `opus` · `sonnet` · `haiku`** — 사용자가 이름 댄 셋(Claude Code 별칭). 목록 밖 값은 저장 · 실행 거부. 이미 저장된 목록 밖 값은
  마이그레이션으로 지운다(전역 → `sonnet`, 상대별 → 비움 = 기본값) — 사용자 데이터 보존(D32)과 D22 "못 읽으면 실행 실패" 사이에서 실행이
  막히지 않게.
- **요청은 사람 글만** — 에이전트 답 · 자동 왕복 글은 요청이 아니다. @멘션은 질의에만(요청은 실행이 없어 부를 에이전트가 없다).
