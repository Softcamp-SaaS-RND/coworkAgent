> **승인 2026-10-17**(사용자 "의견 수용하고 진행해" — 표 전부 · T7 ⓐ). **추가 승인 2026-10-17** Y 11행(Stage 4 발견 — 사용자 "권장 방안으로 진행"). 승인 방법: 구역 단위 · 행 단위 예외 모두 된다. `승인` 칸 ✅ / ❌, ✅ 행은
> `python {TASK}/design/gates.py copy` 가 화면 원본(`crates/app/web/`)에서 기계로 확인한다(E7 — 현재 문구 사라짐 · 제안 문구 있음).
> 표시: **[원문]** 사용자가 직접 정한 literal · **[보안]** 보안 사실을 남긴 문장 · **[T7]** 용어 결정 T7 답에 따름.
> 칸 규약: 문구는 원본 그대로(공백 하나로 접음). `raw:` = 원본의 부분 문자열(같은 낱말이 다른 자리에도 있을 때) · `(지움)` = 빼기만 ·
> `(없음)` = 새로 넣는 문구.

## 규칙(intent 결정 6)

- **R1** 이름(메뉴 · 단추 · 제목 · 라벨 · 툴팁)은 명사 하나. "—" · " · " 로 부연을 잇지 않는다 — 부연은 설명으로.
- **R2** 한 개념 한 이름 — 아래 용어 결정(T).
- **R3** 설명은 한 문장 · 합니다체 · "무엇을 하면 무엇이 된다" 만. 기능 나열 · 이유 풀이 없음, 내용이 곧 설명인 메뉴는 설명 없음.
  보안 사실(초대 자동 등록 · 지문 확인 · 읽기 전용 · 사용량)은 줄여도 남긴다.
- **R4** 빈 화면은 "{무엇} 없음" 한 줄.
- **R5** 라벨과 같은 말 placeholder 는 지운다.
- **R6** 영어는 기술 용어(모델 이름 · effort · markdown · PC · CLI · JSON)만.
- **R7** 알림 · 확인 문장은 합니다체("-했다" → "-했습니다"). 상태 줄 · 툴팁의 부연은 " · " 로 잇는다("—" 대신).

## 바꾸지 않는 것

- 기술 값 · 이름: 모델(`opus` · `sonnet` · `haiku`) · effort 값 · 포트 · 지문 · 경로 · `AI 에이전트(CLI)` · 도구 이름.
- 메타 줄의 " · " 구분(예: "jhlee · QA-LAB-02 · 페어링됨 · 방금 통신", "sonnet · high") — 이름이 아니라 값 나열이다.
- 내 에이전트 "추가 지시 사용 예" 세 줄 — 에이전트에게 주는 지시 예시라 평서 "-다" 가 맞다.
- 오류 앞말 "… 오류:" · "… 실패:" — 불러오기 오류와 동작 실패를 가른다.
- 트레이 메뉴 "열기" · "종료"(S4).
