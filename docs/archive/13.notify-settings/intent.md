# intent — 13.notify-settings

## 왜

자동 왕복(12)은 왕복마다 양쪽 PC 에 인바운드 알림을 1건씩 낸다 — 상한 50 이면 최대 50건. 알림은 지금 전체 켜기 · 끄기 하나뿐이다.
— 출처: 12 report "남은 것", 확인 답(2026-10-11) "1번을 기본 동작으로 사용. 알림 끄기 옵션 제공. 이와 같이 알림/임계값에 대한 설정 옵션
최대한 지원." · 설정 범위 "종류별 알림 켜기·끄기 (권장), 자동 왕복 상한 기본값 (권장), 알림에 본문 미리보기 끄기".

## 범위

- 자동 왕복 알림 기본 = **시작 1건 + 끝 1건**(중간 글은 알리지 않음). 끝 = 상한 · 실패 · 거절 · 상대 멈춤 같은 자동 멈춤(내가 멈춘 것은 알리지
  않음). 자동 왕복 알림 모드: 시작·끝(기본) / 매번 / 끄기.
- 종류별 알림 켜기 · 끄기: 페어링(요청 · 승인) · 받은 요청 · 받은 답 · 자동 왕복(위 모드). 전체 켜기 · 끄기(D29, 기본 OFF)는 그대로 위에.
- 알림 본문 미리보기 끄기 — 끄면 이름 · PC 만, 글 앞부분을 보이지 않는다.
- 자동 왕복 상한 기본값 설정(1 ~ 50, 처음 10) — 새 대화에 상한을 안 주면 이 값. 최대 50 은 고정.
- 웹UI 설정 → 알림에 위 항목.

## 제외

- 에이전트 실행 시간 제한 설정(확인 답에서 고르지 않음).
- 실화면 확인 — `19.prototype-acceptance`(D28).

## 성공 기준

- A1: 자동 왕복 대화에서 양쪽 PC 알림은 시작 1건 · 자동 멈춤 1건뿐이다(기본). 모드 "매번" 이면 글마다, "끄기" 면 없다.
- A2: 종류별 끄기 · 미리보기 끄기가 알림 · 트레이 건수에 반영되고, 재시작 뒤에도 유지된다.
- A3: 상한을 주지 않은 자동 왕복 대화는 설정한 기본값을 쓴다. 범위 밖 값은 저장되지 않는다(400).
- A4: 루트 `PROJECT.md` 검증 명령이 통과한다.
