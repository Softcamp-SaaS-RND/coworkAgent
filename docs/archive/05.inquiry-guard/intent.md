# intent — 05.inquiry-guard

승인: 2026-10-11 (사용자 지시 + 확인 답 "도구도 읽기 전용으로 고정 (권장)")

## 왜

사용자 지시 원문 "해당 툴의 목적은 에이전트에게 진행 중인 프로젝트/제품에 대한 문의를 응답하는게 기본기능이다.그렇기 때문에
claude -p 해드리스 요청시 시스템 프롬프트 추가를 통해 임의로 요청 수신자의 작업에 개입하거나 편집/삭제를 방지한다"(2026-10-11).
지금은 프로필 프롬프트가 있을 때만 `--append-system-prompt` 를 붙이고, 프로필 도구에 Edit · Write · Bash 를 넣을 수 있어 원격 요청이
수신 PC 의 작업을 바꿀 수 있다. — 출처: masterPlan D31(사용자 지시 · 확인 답 2026-10-11) · D16 · D21 · D22 · 루트 `PROJECT.md` 가드레일 6행.

## 범위

- 모든 원격 실행(`claude -p`)에 **문의 응답 전용 시스템 프롬프트**를 항상 덧붙인다(`--append-system-prompt`) — 프로필 추가 지시는 그
  뒤에 "수신자 추가 지시" 로.
- 프로필 허용 도구를 **읽기 전용 목록**으로 고정 — 등록 API 가 목록 밖 도구를 거부하고, 실행 시에도 목록 밖 도구를 걸러 낸다(이전에
  저장된 프로필 포함).
- 웹UI 설정의 에이전트 안내 문구 · masterPlan D31(신규) · D22 개정.

## 제외

- 출력에서 비밀을 걸러 내는 후처리(DLP) — 시스템 프롬프트 지시까지만.
- 웹 도구(WebFetch · WebSearch) — 문의 응답에 필요 없고 외부로 내보내는 경로라 목록에 넣지 않는다.
- 실제 `claude -p` 로 거부 동작 확인 — `19.prototype-acceptance`(D28).

## 성공 기준

- A1: 모든 실행 인자에 문의 응답 전용 시스템 프롬프트가 들어가고, 프로필 추가 지시는 그 뒤에 붙는다.
- A2: 실행 인자의 `--tools` · `--allowedTools` 는 읽기 전용 목록 안의 도구만 담는다 — 프로필에 Edit · Bash 등이 저장돼 있어도 빠진다.
  남는 것이 없으면 기본(Read · Grep · Glob).
- A3: 에이전트 등록 API 는 읽기 전용 목록 밖 도구를 400 으로 거부한다.
- A4: 루트 `PROJECT.md` 검증 명령이 통과한다.

## 결정

- 도구도 읽기 전용으로 고정(프롬프트 + 도구 이중) — 확인 답. 기각안: 시스템 프롬프트만.
- 읽기 전용 목록 = `Read` · `Grep` · `Glob` · `LS` · `NotebookRead` — 권장안(자동 진행 위임). 웹 도구 제외(위 `## 제외`).
- 시스템 프롬프트에 "비밀(키 · 토큰 · 비밀번호 · 개인정보)을 답에 싣지 않는다" 를 함께 둔다 — 지시 범위의 안전 보강(원격으로 나가는
  답이므로, PRODUCT "Claude 실행" 규칙).
