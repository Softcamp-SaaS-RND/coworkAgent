# intent — 1a.security-hardening

승인: 2026-10-13

## 왜

사용자 지시 원문 "아무래도 현재 제품이 제공하는 기능은 로컬서버를 사용하는 만큼 보안에 취약할 수 있을까봐 걱정되. 외부 공격이나 무단 사용에 대한
방어가 잘되어있는지 면밀히 살펴보고 개선작업을 신규 task로 진행해"(2026-10-13).

점검 결과는 [audit](audit.md) — Critical · High 0, **Medium 3 · Low 12 · Info 9**(한 PC 한 사용자 전제 뒤 Medium 1 · Low 13). 원격 피어 · 원격 텍스트 쪽 방어(TLS 키 고정 · XSS · argv 주입 ·
`--restricted` 로 작업 폴더 밖 읽기 · 훅 · 스킬 차단 — 실측)는 견고하다. 남은 결함은 **같은 PC 의 샌드박스 · 로컬 서버**(데이터 폴더 ACL S1 · 포트를 가리지
않는 인증 쿠키 S2)와 **상대에게 새는 실패 정보**(S3), 그리고 원격 입력 총량 · 표시 위장(S5 · S8 · S9 · S10)에 있다.

닿는 [masterPlan](../../masterPlan.md) 항목: D8(신원 · 보안 — 개정의 수용 위험은 유지) · D9(로컬 웹UI 토큰 + Host/Origin) · D22 · D31(원격 실행 권한 ·
문의 응답 전용) · D24(실행 한도 — 동시 실행 상한 없음을 수용) · 루트 `PROJECT.md` 가드레일 6행(원격 메시지는 신뢰하지 않는 입력). 이 Task 가 없으면
같은 PC 의 다른 주체가 신원 키 · 로컬 API 를 가져갈 수 있고, 상대가 실패를 유도해 이 PC 의 경로 · 계정 정보를 얻는다.

## 범위

- **로컬 주체 경계**: 데이터 루트 소유자 전용 권한 — Windows DACL · macOS 0700/0600(S1) · 웹UI 인증을 쿠키 → 헤더 토큰(S2) · 보안 헤더(S4) ·
  데이터 루트를 포함하는 에이전트 폴더 거부(S7) · DLL 검색 경로(S11).
- **원격 입력 경계**: 실패 답 일반화(S3) · 초대 코드 IP 별 실패 상한(S5) · uuid 형식 · 메모 상한(S8 중 D24 밖) · 이름 서식 문자 · 거절 사유 정리(S9) ·
  프롬프트 머리말 · 구분자(S10) · CLI 출력 제어 문자(S14) · `Mutex` 오염 복구(S13).
- **회귀 방어**: `--restricted` 가 작업 폴더 밖 읽기 · 프로젝트 훅을 막는지 확인하는 canary 검사(G1 — CLI 가 바뀌면 드러나게).
- 매뉴얼(사용자 · 개발자)의 보안 절 갱신.

## 제외

- D8 개정의 수용 위험(초대 생성 측 승인 생략 · 주소+코드 직접 추가의 지문 미고정) — 사용자가 이미 수용.
- 방화벽 규칙 자동 등록(I1) — 관리자 권한이 필요해 단일 실행 파일 · 사용자 권한 설치와 맞지 않는다. 매뉴얼 안내 유지.
- 연결 슬롯 고갈(S15) — 원장 `#01 R2-F2` 그대로(Phase 2 수신 정책).
- 동시 실행 상한 · 대기열 · 포트 관리 — [1b](../1b.inbound-capacity/intent.md).
- 코드 서명 · 업데이트 서명(D12) — Phase 3 · 4.
- 한 PC 의 여러 로그인 사용자(결정 1) — 그래서 남은 `instance.json` 포트 점유(S6)도 뺀다.
- OS 전용 암호화로 키 감싸기(DPAPI 등 — 결정 2).
- 로컬 API 의 gRPC 전환 — 결정 4(기각).
- 받는 쪽 자동 왕복 멈춤을 연 쪽이 해제(S12) — 결정 6.
- 같은 사용자 권한으로 도는 악성 프로세스 — 그 주체는 이미 사용자 파일 전부를 읽는다(OS 경계 밖).

## 성공 기준

- A1: 데이터 루트(키 · `instance.json` · DB 포함)를 소유자 전용 권한으로 만들고 기존 설치도 시작 때 맞춘다 — Windows `icacls` 에 소유자 · SYSTEM 외 주체가
  없고(상속 없음), macOS 는 폴더 0700 · 파일 0600.
- A2: 로컬 API 가 쿠키로 인증되지 않는다 — 다른 `127.0.0.1` 포트로 보내진 요청이 토큰을 얻지 못하고, 웹UI 는 헤더 토큰으로 지금 기능을 그대로 쓴다.
- A3: 모든 웹UI 응답에 `X-Frame-Options: DENY` · CSP `frame-ancestors 'none'` · `X-Content-Type-Options: nosniff` 가 붙고 HTML 본문 보기가 깨지지 않는다.
- A4: 실행이 실패하면 상대에게 가는 답에 stderr · 경로 · 오류 원문이 없다. 내 화면 · 로그에는 원인이 남는다.
- A5: 같은 출처 IP 가 초대 코드를 N 회 틀리면 그 창 동안 그 IP 는 거절되고, 다른 IP 의 정상 수락은 된다.
- A7: 데이터 루트를 포함하는 폴더는 에이전트 폴더로 등록 · 수정되지 않는다.
- A8: 원격 `conv` · `msg` · `reply_to` 는 UUID 형식만 받고, 실행 프롬프트에 붙는 메모는 개수 · 바이트 상한을 넘지 않는다.
- A9: 원격 이름에서 서식 문자(Cf)가 지워지고, 거절 사유는 정해진 코드만 표시된다.
- A10: 원격 본문은 늘 머리말 뒤 · 구분자 안에 들어가 프롬프트 맨 앞에 오지 않는다.
- A11: `--restricted` canary 검사가 작업 폴더 밖 Read 거부 · 프로젝트 훅 미실행을 확인한다(실제 `claude` 필요 — 수동 gate 또는 개발 PC 전용 테스트).
- A12: 기존 테스트 · 웹UI 테스트 green, 경고 0.
- A13: 릴리스 exe 가 `VCRUNTIME140.dll` 을 동적으로 불러오지 않는다(import 표) — 실행 폴더에 같은 이름 DLL 을 두어도 로드되지 않는다.
- A14: CLI 평문 출력에서 원격 답의 C0 · C1 제어 문자(`\n` `\t` 제외)가 지워지고, DB 잠금이 한 번 오염돼도 이후 요청이 계속 처리된다.
