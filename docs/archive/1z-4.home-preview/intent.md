## 범위

- 개요에 보기 둘 — **미리보기**(기본) · **목록**(지금 접는 절 그대로). 머리 오른쪽 "목록 | 미리보기" 전환, 설정 `ui_home_view`(`preview` 기본 · `list`)에 기억.
- 미리보기 = 시안 B: '나' · 그룹 개요는 상대마다 작은 대화 창 — 머리(상대 아이콘 · 이름 · 접속 · 대기 요청 · "대화 열기 →"), 대화방 탭(상태 점 · 안 읽음),
  본문 = 고른 대화방의 최근 글 말풍선(이 PC 쪽 오른쪽, 에이전트 글 · 실행 중 · 오류 구분), 누르면 그 대화. 대화 없는 상대는 "+ 새 세션".
- 상대 타일 개요는 대화방마다 창(머리 = 대화 제목 · 상태 · 에이전트, 탭 없음).
- 창 배치 = 브라우저 폭에 맞춘 열 수(창 최소 폭 아래로 줄지 않게), 창 높이 고정, 넘치면 세로 스크롤.
- 대화 글 API 에 선택 인자 `limit`(마지막 N 개, 오래된 것부터) — 미리보기가 대화 전체를 읽지 않게.

## 제외

- 미리보기에서 답장 · 읽음 처리(미리보기는 읽음을 바꾸지 않는다 — 대화를 열어야 읽음).
- 상대 순서 바꾸기(지금 순서 그대로), 탭 선택 저장, 마크다운 그리기(미리보기는 글자만).

## 성공 기준

- A1: 개요 기본 보기가 미리보기이고, 목록으로 바꾸면 설정에 남아 다시 열어도 목록 — 틀린 값은 400(시험 · 실제 화면).
- A2: '나' · 그룹 개요 미리보기 = 상대마다 창, 처음 탭 = 최근 활동 대화방, 탭을 누르면 그 대화방 글로 바뀌고 5초 새로 고침에도 유지(시험 · 실제 화면).
- A3: 상대 타일 개요 미리보기 = 대화방마다 창(실제 화면).
- A4: 창 열 수가 브라우저 폭에 따라 바뀌고(넓으면 여럿, 좁으면 하나) 넘치면 세로 스크롤(실제 화면 계산 값).
- A5: 미리보기는 대화 전체를 읽지 않고(`limit` — 서버가 SQL 에서 마지막 N 개만) 5초 새로 고침마다 읽지 않으며 필요한 대화만 다시 읽고(요약이 바뀜 · 변경 신호 · 개요에 들어옴 · 탭 고름), 미리보기만으로 안 읽음이 줄지 않는다(시험 · 실제 화면).
- A7: 창의 대화방 탭은 3개까지(고른 대화는 늘 보임), 넘치면 "+n개" — 누르면 그 상대 개요(대화마다 창)(시험 · 실제 화면).
- A6: 회귀 없음 — PROJECT.md 검증 명령 PASS, 매뉴얼 반영.
