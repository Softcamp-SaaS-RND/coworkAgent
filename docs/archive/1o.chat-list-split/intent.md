## 왜

사이드바 대화방 목록에 내가 연 대화(내가 상대 에이전트에게 묻는 대화)와 상대 PC 사용자가 연 대화(내 에이전트가 답하는 대화)가 한 목록에 섞여 있어
지금 내가 챙길 대화를 한눈에 가르기 어렵다. 말풍선은 내 글이 강조색으로 꽉 차고 상대 글은 타일 색 층 · 띠가 깔려 음영 대비가 강해 긴 답을 읽기 힘들다.
— 출처: masterPlan D26(대화 UI) · D35(사이드바 · 타일) · S4(웹UI), 오버플로 `1o.chat-list-split`. 대화(2026-10-16) 사용자 원문: "대화방의 대화 목록 그룹화하여
구분.(또는 구분선으로 구분) - 내 대화 : 사용자가 다른 agent 와 채팅한 내용 - agent 대화 : 다른 PC의 사용자의 대화에 응답한 내 agent 대화 내역. 공통사항 : 대화
말풍선의 음영을 대비를 낮춤. 현재 너무 음영이 강해서 가독성이 떨어짐." · 추가 지시: "1o task 병렬 진행. 왜냐하면 코드 중복되지 않음. 음영 관련해서는 디자인
시안 3개 생성해서 결정. 내가 연 자동왕복 대화는 \"내 대화\"에 포함."

코드 사실(2026-10-17 조사):
- 대화방 목록 = 사이드바 `#conv_sections`(`app.js` `renderConvList` → `view.js` `convSections`). 상대 타일 · 그룹은 한 절 "대화방", 레일 "나" 는 상대별 접는 절(#1g).
  줄은 `convItem`(☆ · 아바타 · 제목 · 미리보기 · 시각 · 안 읽음 · 자동 왕복 칩). 손으로 놓은 순서 · 끌어 옮기기(#1i `sortByPos` · `data-section`).
- 같은 줄 모양을 즐겨찾기 화면(`renderStarred` · `starredSections`)도 쓴다. 상대 개요(`peerSummary`)는 상대별 요약.
- 화면은 대화마다 `dir`(`out` = 내가 연 대화, 자동 왕복 포함 · `in` = 상대가 연 대화) · `relay_agent` 를 이미 받는다(`/api/conversations`) — 서버 변경 없이 가를 수 있다.
- 말풍선 색(`app.css` 681 ~ 689, #1l): 내 글 `.msg.side-mine .bubble` = 바탕 `var(--accent)`(라이트 `#4E55D9`) 꽉 채움 + 글자 `var(--on-accent)`.
  상대 글 `.msg.side-theirs .bubble` = `var(--surface)` + 타일 색 층(`::before`, 불투명도 0.12) + 왼쪽 띠 3px. `color-mix` 는 쓰지 않는다(macOS 12 Safari 15).

## 범위

- 대화방 목록을 **내 대화**(`dir = out` — 내가 연 대화 · 내가 연 자동 왕복)와 **agent 대화**(`dir = in` — 상대 PC 사용자가 연 대화에 내 에이전트가 답)로
  구분한다. 구분 모양은 시안에서 고른다(그룹 머리 · 구분선 · 탭).
- 말풍선 음영 대비를 낮춘다(내 글 · 상대 글 모두, 다크 · 라이트). 단계는 시안에서 고른다.
- 디자인 시안 3개(목록 구분 + 음영 한 묶음) — 디자인 캔버스 판 "1o" 줄(가상 데이터, 다크 · 라이트).
- 사용자 가이드 · 캡처 · `ux_literals` · node 화면 시험.
- (개정) **레일 우클릭** — 레일 아이콘 우클릭 때 브라우저 메뉴와 타일 메뉴가 겹쳐 뜨는 것을 고친다. 사용자 원문(1016-cowork.md): "레일 아이콘에서 우클릭 시
  브라우저 우클릭 매뉴와 레일 아이콘의 우클릭 매뉴가 중첩 실행됨. 레일 아이콘에서는 브라우저 우클릭 매뉴를 미사용하거나 레일 아이콘 클릭 시 우클릭 매뉴
  출력하도록 변경 검토."
- (개정) **관람자 초대** — 내 대화 · agent 대화에 페어링된 상대를 관람자(읽기 전용)로 초대한다. 사용자 원문(1016-cowork.md): "내 대화, agent 대화에 사용자 추가
  기능 제공. 추가된 사용자는 관람자이며 프롬프트는 비활성화. 대화 내용만 공유하며 읽기 전용 사용자로 동작. 즉, 옵져버와 같이 해당 대화방의 내용만 공유하는
  사용자로 초대기능 추가." 통신 · 저장 · 화면이 모두 바뀐다.

## 성공 기준

- A1: 사이드바 대화방 목록이 내 대화 · agent 대화로 나뉘어 보이고(고른 시안 모양), 내가 연 자동 왕복 대화는 내 대화에 있다.
- A2: 상대 타일 · 그룹 · 레일 "나" 의 목록이 모두 같은 규칙으로 나뉜다(미해소 2 · 3 확정안대로).
- A3: 말풍선 음영이 고른 시안 단계로 낮아지고, 내 글 · 상대 글 구분과 글자 대비(4.5:1 이상)가 다크 · 라이트 모두 유지된다.
- A4: 기존 목록 기능(☆ · 안 읽음 · 실행 중 · 자동 왕복 칩 · 검색 · 끌어 옮기기 · 접기) 회귀 없음.
- A5: 검증 명령(`cargo test --workspace` · clippy · node 화면 시험 · `check_gates` · `check_ddd_docs`) 통과.
- A6: (개정) 레일(타일 · 타일 사이 빈칸 · 레일 바탕) 어디서 우클릭해도 브라우저 메뉴가 뜨지 않고, 타일 위에서는 타일 메뉴만 뜬다.
- A7: (개정) 내 대화 · agent 대화에 페어링된 상대를 관람자로 넣으면, 관람자 PC 목록의 "공유 대화" 묶음(초대한 사람 타일 아래)에 그 대화가 이전 이력 전체와 함께
  보이고, 이후 글 · 답 · 편집 · 삭제가 따라간다. 관람자 화면에는 입력창이 없고 글을 쓸 수 없다.
- A8: (개정) agent 대화에 관람자를 넣으면 그 대화를 연 상대 화면에 관람자 표시와 알림이 뜬다(승인 없음).
- A9: (개정) 초대한 사람이 빼거나 관람자가 나가면 이후 글은 가지 않고, 관람자 PC 의 사본은 읽기 전용으로 남는다. 꺼진 관람자에게는 보관했다 보낸다 —
  **24시간까지**(넘으면 그 관람이 끝나고 돌아온 사본은 "공유 해제됨" — 개정 승인 2026-10-17, 사용자 "관람자에 한해서는 24시간 한정 승인").
- A10: (개정) 공유 대화는 실행(`claude -p`) · 자동 왕복 · 요청 목록 · 멘션 · CLI 에 끼어들지 않는다. 이 기능이 없는 상대(0.5.0)는 초대하지 못하고 사유가 보인다.

## 결정

- 구분 기준 = 대화의 `dir`(`out` = 내 대화, `in` = agent 대화). 자동 왕복은 연 쪽 기준 — 내가 연 자동 왕복 = 내 대화(사용자 원문 "내가 연 자동왕복
  대화는 \"내 대화\"에 포함."). 기각: 마지막 글 발화자 기준(대화가 오가며 칸이 바뀐다).
- 구분 모양 · 음영 단계 = **시안 Ⓐ** — 섹션 머리 "내 대화 n" · "agent 대화 n"(개수 포함), 말풍선 내 글 강조색 층 14% + 오른쪽 띠 · 상대 글 타일 색 층 7%
  (사용자 원문 "디자인 시안 3개 생성해서 결정" → 선택 "의견 수용. 권장 방안으로 진행."). 기각: Ⓑ 구분선 · 더 약한 음영, Ⓒ 탭 · 테두리만(한쪽을 가린다).
- 레일 "나" = 상대별 절 **안에서** 내 대화 · agent 대화로 나눈다(상대별 접기 그대로). 기각: 맨 위에서 둘로 나누고 그 안을 상대별로.
- 즐겨찾기 화면 = 그대로(사이드바 목록만 나눈다). 기각: 같은 규칙 적용.
- 끌어 옮기기(#1i) = 같은 묶음 안에서만(묶음은 `dir` 로 정해진다).
- 빈 묶음 = 머리를 숨긴다(한쪽만 있으면 지금처럼 한 목록).
- @멘션 대화(#18) = 그 대화의 `dir` 를 따른다.

### 개정(2026-10-17 — 1016-cowork.md 인터뷰)

- 레일 우클릭 = 레일 전체에서 브라우저 메뉴를 막고 타일 위에서만 타일 메뉴. 기각: 앱 전체에서 막기(입력창 · 본문 복사 메뉴가 사라진다) · 왼쪽 클릭으로 메뉴.
- 관람자 초대 대상 = 페어링된 상대 PC 만. 기각: 페어링 안 된 사람(초대 코드 — 관람 전용 연결을 새로 만들어야 한다).
- 공유 범위 = 초대 시점까지 이력 전체 + 이후 글 · 답 계속(빼기 · 나가기 전까지). 기각: 초대 시점 사본만 · 이후 글만.
- 반영 범위 = 글 · 답 · 편집 · 삭제(#1f). 실행 중 진행 표시는 보내지 않는다. 기각: 진행 표시까지 · 새 글 · 답만.
- agent 대화(상대가 연 대화)의 관람 = 대화를 연 상대에게 알림만(관람자 표시 · 알림, 승인 없음). 기각: 상대 승인 필요 · 내 대화만 허용.
- 관람자 화면 = 사이드바 목록의 세 번째 묶음 **"공유 대화"**(초대한 사람 타일 아래), 입력창 없음(사용자 원문 "'관람 대화' 용어를 '공유 대화'로 변경.").
  기각: 별도 메뉴 화면.
- 해제 = 초대한 사람이 빼기 + 관람자가 나가기, 빠진 뒤 관람자 사본은 읽기 전용으로 남김. 기각: 빠지면 관람자 사본도 지움.
- 진행 = 1o 에 합친다(사용자 선택 "1o 에 관람자까지 합치기"). 기각: 새 Task 1p.
- (2026-10-17 둘째 지시) 관람자 수 상한 = 대화당 5명. 관람자 PC 는 보기만(편집 · 삭제 없음). 빠진 사본은 **"공유 해제됨"** 태그만 붙인다. 원문: 사용자 "관람자 수 상한 : 5명. 관람자 PC 는 view 만 제공. 편집, 삭제 없음. '공유 해제됨' 태그만 추가. UI 추가수정 사항. 내용이 곧 설명이되는 매뉴에 대해서는 매뉴에 대한 설명을 제거한다."
- (2026-10-17 둘째 지시) **내용이 곧 설명인 메뉴의 설명을 지운다** — 개요 머리 "상대별 대화 요약 — …" · 개요 카드의 접속 · 대화 수 · 최근(예 "방금 통신 대화 2 최근 22:42") ·
