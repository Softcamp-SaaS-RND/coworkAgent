# 매뉴얼 라우팅 인덱스 · 등록 규약

> **"무엇을 하려면 어느 문서를 여는가"** 와 매뉴얼 등록 규약. 내용은 각 문서가 갖는다.
> 매뉴얼을 추가·이동하면 **아래 표를 함께 고친다.** 등록·갱신 시점은 Task 종결
> ([etc/ddd-workflow.md](../etc/ddd-workflow.md) "개발 Flow" 6).

**먼저 읽는다**: 매 세션 필독은 루트 `CLAUDE.md` 가 정한다. 코드를 고치기 전에는 루트 `PRODUCT.md` 의 손댈 절 → 아래 매뉴얼의 그 절만.

| 나는 … | 폴더 | 무엇이 있나 |
| --- | --- | --- |
| 이 프로젝트의 **코드를 고친다** | `dev/` | 모듈 매뉴얼 · 개발·측정 절차 문서 |
| 이 프로젝트를 **돌려 쓴다** | `user/` | 설치·실행 안내 |

## 등록 규약

- **독자로 폴더가 갈린다.** `dev/` = AI 에이전트·개발자용(모듈 매뉴얼 + 개발 절차), `user/` = 그
  산출물을 쓰는 사람용(실행 안내). 한 문서가 두 독자를 겸하지 않는다 — 둘 다 필요하면 **쪼개서
  양쪽에 둔다**.
- 위치: `dev/{모듈 전체 이름}.md` — 언어 관례의 정규 모듈 경로가 파일명.
- 모듈 매뉴얼 필수 절: **개요 / 공개 계약(경로·API) / 사용 예**. 선택: 금지 사항 · 참고 문서.
  해당 없는 절은 두지 않는다 — 채우기 위한 문장을 쓰지 않는다. 절차·운영 문서는 이 형식의
  예외이며 서두에 그 사실을 명시한다.
- **작성·갱신 시점 = Task 종결 시.** 그 Task 가 손댄 모듈의 매뉴얼을 등록하거나 갱신한다(변경 이력은
  git log — 문서에 버전 표를 두지 않는다). stage 중에 쓰면 재작업이 된다. 커밋은 `report.md` 와
  함께 또는 직전 `docs:` 커밋으로.
