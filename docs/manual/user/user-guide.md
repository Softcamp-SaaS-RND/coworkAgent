# 사용자 가이드 — coworkAgent

> 쓰는 사람용 실행 안내다. 같은 사내망에 있는 다른 사람 PC 의 Claude 에이전트에게 그 PC 의 프로젝트를 묻고 답을 받는다.
> 동작 원리(프로세스 · 세션 · 저장 구조 · 흐름)는 [개발자 가이드](../dev/developer-guide.md). 화면 글자는 앱에 보이는 그대로 적었다.
> 예시의 이름(`user-b` · `review` · `D:\work\shop-api`)은 가상의 것이다.

## 1. 무엇을 하는 앱인가

- 두 PC 를 한 번 **연결(페어링)** 해 두면, 내가 쓴 질문을 **상대 PC 에 등록된 에이전트**가 그 PC 의 Claude Code 로 답한다.
- 답은 상대 PC 에서 `claude -p`(헤드리스 실행)로 만들어진다 — 상대의 Claude 구독 사용량을 쓰고, 상대가 정한 폴더 안에서
  **읽기 전용 · 문의 응답 전용**으로만 동작한다(파일을 고치거나 명령을 실행하지 않는다).
- 주고받은 글과 답은 두 PC 에 모두 남는다. 상대 PC 가 꺼져 있으면 내 PC 에 보관했다가 켜지면 보낸다(7.2). 같은 대화에 이어 쓰면 에이전트가
  앞 맥락을 이어서 답한다.
- PC 끼리는 중앙 서버 없이 직접 암호화(TLS)해 주고받는다. 파일 전송은 없다.
- 다만 답을 만드는 Claude Code 는 **질문과 에이전트가 읽은 파일 내용을 Claude 모델 서비스(그 PC 의 Claude Code 가 쓰는 제공자 — Max 구독
  로그인이면 Anthropic)로 보내** 답을 받는다. 답하는 PC 는 인터넷 연결이 필요하고, 프로젝트 내용이 사내망 밖 모델 서비스로 나간다.
- **사내망(LAN) 안에서 쓰는 도구**다. 다만 앱이 인터넷 주소를 막지는 않는다 — 수신 포트를 공유기 포트 포워딩 등으로 인터넷에 열지 않는다.

## 2. 준비

| 항목 | 내용 |
|---|---|
| OS | Windows 10/11 x64(macOS 는 준비 중) |
| 설치 | 없다 — `coworkAgent.exe` 파일 하나. [GitHub 릴리스](https://github.com/tskimS/coworkAgent/releases)에서 받는다(사전 배포 · 코드 서명 없음 — SmartScreen 경고가 뜰 수 있다). 직접 빌드는 [개발자 가이드](../dev/developer-guide.md) "빌드 · 실행" |
| 네트워크 | 상대 PC 와 같은 LAN. 앱의 수신 포트(기본 TCP 47100 — 프로필 → 사용자 정보 "수신 주소")를 방화벽이 막으면 사내망 쪽만 허용(인터넷 쪽으로 열지 않는다) |
| Claude Code | **답하는 PC**(에이전트를 등록한 PC)에 Claude Code 2.1.267 이상 설치 · 로그인, 그리고 Claude 모델 서비스로 가는 인터넷 연결. 낮으면 `claude update`. 묻기만 하는 PC 는 없어도 된다(자동 왕복으로 내 에이전트를 돌릴 때는 필요) |

## 3. 실행 · 열기 · 종료

1. `coworkAgent.exe` 를 실행한다 → 작업 표시줄 알림 영역에 **트레이 아이콘**이 생긴다. 창은 뜨지 않는다. 실행하면 **로그인할 때 자동 실행**에
   등록된다(Windows 시작 프로그램 · macOS 로그인 항목 — 끄기는 설정 → **시작 — 자동 실행**, 끈 뒤에는 다시 등록하지 않는다). 실행 파일을 옮겼으면
   한 번 실행하면 새 경로로 고쳐진다.
2. 트레이 아이콘 메뉴 **"열기"** → 기본 브라우저에 웹UI 가 열린다. 이미 실행 중일 때 `coworkAgent.exe` 를 다시 실행해도 웹UI 가
   열린다. 두 번째 실행은 열기를 넘기고 끝난다 — 떠 있는 앱이 응답하지 않으면 최대 1분쯤 기다린 뒤 실패로 끝난다.
3. 트레이 메뉴 **"종료"** → 앱이 끝난다. 꺼 둔 동안 상대가 보낸 글은 상대 PC 에 "보내는 중" 으로 보관됐다가, 이 PC 를 다시 켜면 들어온다.
   이 PC 가 보내다 만 글도 다시 켜면 이어 보낸다.

- 앱이 비정상 종료되면(작업 관리자 강제 종료 포함) **1초 뒤 저절로 다시 켜지고** 남은 대기열 · 보낼 글을 이어 간다. 1분 안에 3번이면 다시 켜지
  않고 붉은 트레이 아이콘 — 사유 "앱이 60초 안에 3번 비정상 종료 — 다시 띄우지 않습니다". 원인은 로그의 "패닉: …" 줄(15장 `logs\`).
- 로그인 직후처럼 작업 표시줄 알림 영역이 아직 준비되지 않아 트레이 아이콘을 만들지 못하면 1 · 2 · 4 · 8 · 15 · 30초 뒤(모두 1분) 다시 만든다 —
  끝내 못 만들면 사유 파일(아래)을 열고 끝난다.
- 시작에 실패하면 **붉은 트레이 아이콘**이 뜨고 툴팁에 사유가 보인다. "오류 보기" 를 누르면 사유 파일
  (임시 폴더의 `coworkAgent-start-error.txt`)이 열린다.
- 알림을 켜 두었다면 새 요청이 올 때 트레이 아이콘에 **주황 점**, 툴팁 "coworkAgent — 새 요청 N건". 웹UI 를 열면 지워진다.
- 앱을 다시 켜거나, 탭을 닫았다가 주소로 다시 들어가거나, 새 탭을 직접 열면 화면 위에 "연결이 끊겼습니다 — 트레이 아이콘 메뉴 '열기' 로 다시
  여세요" 가 뜬다 — 트레이 "열기" 로 다시 연다(웹UI 열쇠는 그 탭에만 있다).

## 4. 화면 둘러보기

| 영역 | 무엇이 있나 |
|---|---|
| 상단 바 | 통합 검색(Ctrl K — "검색 — 메시지 · 대화 · 사람 · 에이전트") · "+ 새로 만들기"(새 대화 · 초대 생성 · 초대 수락 · 에이전트 등록) · 알림 종(내 활동) · 프로필 단추(아이콘 — 없으면 사람 모양 + 표시 이름 한 번, 긴 이름은 "…", 마우스를 올리면 전체). 아이콘 테두리 · 점 색 = 내 상태(초록 받기 가능 · 주황 집중 · 붉은 앱과 연결 끊김 — 11장) |
| 레일(왼쪽 끝) | "나"(모든 상대를 상대별로 묶어 봄) · 연결한 PC 타일(그 상대만 — 접속 점 · 안 읽음 배지) · "+"(설정 → 연결 페어링 카드를 맨 위로, 초대 수락 칸을 펼쳐 PC 추가) · 구분선 아래 그룹 타일(4.1) · "그룹 +" · 설정. 상대 · 그룹 묶음의 앞뒤는 설정 → 화면 "타일 순서"(기본 사용자 → 그룹). 타일 = 사람 모양("나" · 상대) · 사람 + 그림자 모양(그룹) 아이콘, 그림을 넣으면 그림 — 이름은 타일 아래(길면 "…", 마우스를 올리면 전체) |
| 사이드바 | 고른 타일의 메뉴(이름 앞 아이콘 · 절 사이 구분선 — 아래 표) · 대화방 목록 · 제목 검색. 머리의 ✎ = 타일 편집(표시 이름 · 아이콘), ⋯ = 타일 메뉴(4.2) |
| 대화 | 말풍선 대화와 입력창(7.2). 머리글에 ☆ · 제목 · 상대 · 에이전트 · 접속 상태 · **"대화 보기 / 원문 보기"** 전환 · **"북마크 n"**(이 대화에서 북마크한 글 수 — 누르면 세부정보의 북마크 항목) · **"세부정보"** |
| 실행 상세(오른쪽) | 진행 · 대화 정보 · 자동 왕복 · 요청 · 북마크 항목. 창 폭이 1280 미만이면 닫힌 채 시작한다 — 머리글 "세부정보" 로 연다 |
| 설정 | 한 열 — 페어링 · 연결 목록 · 내 에이전트 · 실행 — 모델 · effort · 화면 — 테마 · 타일 순서 · 시작 — 자동 실행 · 알림. 카드 설명은 제목 옆 **'?'** 에 마우스를 올리거나 초점을 두면 뜬다. 내 정보는 설정이 아니라 프로필 → **"사용자 정보"** 팝업 |

**레일 범위** — 무엇을 고르냐에 따라 사이드바 메뉴와 목록이 바뀐다.

| | "나" | 상대 타일 | 그룹 타일 |
|---|---|---|---|
| 메뉴 | 개요 / 내 활동 · 요청 · 주고받은 글 / 즐겨찾기 · 북마크 항목 · 에이전트 | 요청 / 즐겨찾기 · 북마크 항목 · 에이전트 | 개요 / 요청 / 즐겨찾기 · 북마크 항목 |
| 목록 | 상대별 접이식 절(제목 = 상대 이름 · 건수, 레일 순서, 글 없는 상대는 숨김). 에이전트는 '내 에이전트' 절이 맨 앞 | 그 상대 것만 | 그 그룹 대화의 것만, 상대별 접이식 절 |
| 첫 화면 · '개요' | 상대별 요약 — 대화 수 · 안 읽음 · 대기 요청 · 최근 활동 + 그 상대 대화(누르면 그 대화) | 그 상대 하나의 요약("개요 · {이름}") | 그룹 요약 — 그룹에 대화가 있는 상대만 |
| 사이드바 대화방 목록 | 상대별 절(절마다 + = 그 상대와 새 대화) | 그 상대 대화방 | "대화 추가" · 상대별 절 |

- 절 머리를 누르면 접히고, 접은 절은 다음에 열어도 접혀 있다(이 PC 에만).
- 내 활동 · 주고받은 글은 "나" 에만 있다 — 상대 타일 · 그룹 타일을 고른 채 종(내 활동)을 누르면 "나" 로 바뀐다. 상대 · 그룹에서는 대화방 목록이
  같은 글을 보인다.
- **주고받은 글** 줄 = 왼쪽 상대 타일(레일과 같은 모양 · 색, 그림을 넣었으면 그림) · 이름 옆 에이전트 칩(내가 연 대화 = 상대 에이전트 이름, 상대가 연 대화 =
  "내 {에이전트}") · 시각 · 미리보기. 누르면 그 대화로.
- **에이전트** 화면: 상대 에이전트를 누르면 그 에이전트와 새 대화(7.1). 내 에이전트 줄 오른쪽 **✎**(또는 줄)를 누르면 설정 → 내 에이전트에서 그
  에이전트 상세가 펼쳐진다(6장).
- **대화방 줄** = ☆ · 아바타 · 제목 · 마지막 글 미리보기("말한 이: 본문") · 시각 · 안 읽음 수. ☆ 를 누르면 즐겨찾기에 넣고(★ 노랑) 다시 누르면 뺀다 —
  대화 머리글 ☆ 와 같은 상태다. **'즐겨찾기'** 메뉴는 그 범위의 ★ 대화방을 모아 보인다("나" 는 상대별 절, 메뉴에 ★ 수).
- 목록 순서는 손으로 놓은 순서다(4.3) — 새 글이 와도 자리가 바뀌지 않고, 새 대화는 맨 위에 생긴다. 새 글은 안 읽음 점 · 굵은 제목 · 배지로 알 수 있다.

### 4.1 그룹 — 프로젝트별 대화 묶음

한 프로젝트를 여러 동료와 함께 할 때, 그 프로젝트의 대화만 모아 본다. 그룹은 **이 PC 에만** 있다 — 상대에게 보이지 않고, 글은 지금처럼 상대와
1:1 로 오간다. 한 대화 · 한 상대를 여러 그룹에 넣을 수 있다.

- **만들기** — 레일 "그룹 +" → 이름(1 ~ 40자, 같은 이름은 안 됨) → "만들기". 만든 그룹이 바로 골라진다. 설정 연결 목록 "+ 그룹 추가" 로도 만든다(5장).
- **대화 넣기** — 셋 중 편한 것:
  - 대화 줄에 마우스를 올리면(또는 초점) 보이는 ⋯ · 대화 머리글 ⋯ → "그룹" 아래 그룹마다 체크(누를 때마다 넣고 뺀다).
  - 그룹을 고른 채 사이드바 "대화 추가" → 제목 · 상대로 검색 → 체크 → "적용"(여러 대화를 한 번에, 체크를 풀면 뺀다).
  - 대화 줄을 끌어 레일의 그룹 타일에 놓는다.
- **상대 넣기** — 상대를 넣으면 그 상대와의 대화 **전부**(앞으로 생길 대화 포함)가 그 그룹에 보인다.
  - 상대 타일 메뉴(4.2) "그룹 — 체크하면 넣고, 풀면 뺀다" 아래 그룹마다 체크(옆 "대화 n" = 그 그룹에 보이는 대화 수) · "+ 새 그룹에 넣기…".
  - 설정 연결 목록에서 줄을 다른 그룹 절로 끌어 옮기거나 줄의 "그룹 ▾" 로 체크(5장).
  - 넣으면 상태 줄에 예: `이준호를 그룹 "결제 모듈" 에 넣었습니다 — 이준호와의 대화 5개가 함께 보입니다`.
- **빼기** — 그룹 대화 줄 ⋯ → "그룹에서 빼기"(대화 하나) · 상대 체크 풀기(상대). 대화 자체는 그대로다. 상대를 빼도 대화를 하나씩 넣은 것은 남는다.
- 그룹을 고른 채 "+ 새로 만들기" → "새 대화" 로 만든 대화는 그 그룹에 들어간다.
- 연결을 지운 상대의 대화도 그룹에 남아 상대 절 뒤에 보인다.
- 예전 버전의 연결 목록 '그룹' 이름표는 새 버전을 처음 켤 때 같은 이름의 레일 그룹으로 옮겨진다(없으면 만든다 — 그 상대가 그 그룹에 들어간다).
  에이전트의 '그룹' 이름표는 없어졌다.

### 4.2 타일 메뉴 — 이름 · 이미지 · 그룹 삭제

레일 타일("나" · 상대 · 그룹)을 우클릭하거나, 타일에 초점을 두고 메뉴 키(또는 Shift + F10), 또는 사이드바 머리 ⋯ 를 누른다.

| 항목 | 하는 일 |
|---|---|
| 타일 편집 | 그 타일을 고르고 사이드바 머리에 편집 칸을 연다 — 표시 이름(그룹이면 그룹 이름) · 아이콘 그림(가운데를 정사각형으로 잘라 작게 저장) |
| 이미지 지우기 | 그림이 있을 때만 — 사람 모양 아이콘으로 돌아간다 |
| 그룹 체크 | 상대 타일에만 — 그 상대를 넣을 그룹 체크 · "+ 새 그룹에 넣기…"(4.1) |
| 위로 옮기기 · 아래로 옮기기 | 상대 · 그룹 타일 — Alt + ↑ / ↓ 와 같다(4.3). 맨 위 · 맨 아래면 꺼진다 |
| 그룹 삭제 | 그룹 타일에만 — 한 번 더 묻고 그룹만 지운다(대화는 지우지 않는다) |

타일 이름 · 그림은 이 PC 에만 저장된다.

### 4.3 자리 옮기기 — 끌어 놓기 · Alt + ↑ / ↓

따로 정렬 기능은 없다 — 손으로 놓은 자리가 그대로 남는다(앱을 다시 켜도).

- **끌어 놓기** — 상대 타일끼리 · 그룹 타일끼리 · 같은 절(같은 상대 · ★) 안의 대화끼리. 놓을 곳 위쪽 반이면 앞, 아래쪽 반이면 뒤에 들어간다.
  "나" · "+" · "그룹 +" · 설정은 옮기지 않고, 상대 ↔ 그룹 · 다른 상대 절로는 놓이지 않는다.
- **키보드** — 타일이나 대화 줄에 초점을 두고(마우스로 누른 뒤 바로도 된다) Alt + ↑ / ↓ 로 한 칸. 타일 메뉴 "위로 옮기기 · 아래로 옮기기" 도 같다.
  화면 읽기 프로그램에는 "n번째로 옮김" 이 읽힌다.
- 대화 자리는 대화마다 하나다 — 그룹에서 옮긴 앞뒤가 "나" · 상대 타일에서도 같다. 상대 타일을 옮기면 "나" · 그룹의 상대별 절 순서도 따라 바뀐다.
- 상대 타일 색은 자리와 상관없이 그 상대에 붙어 있다.

!['나' — 개요 = 상대별 요약, 메뉴 세 절 · 사이드바 대화방 상대별 절](../../images/home.png)

- 프로필 단추(우상단) 메뉴: 머리 "상태 — 아이콘 테두리 색" 아래 **"받기 가능"**(새 요청을 받는다) · **"집중"**(새 요청을 거절) 중 하나 고르기 ·
  "앱과 연결 끊김"(자동 표시 — 고를 수 없음, 11장), 그 아래 **"사용자 정보"**(이름 · PC 이름 · 지문 · 수신 주소 · 포트 · 버전 · 데이터 경로 · DB 팝업 — Esc ·
  "닫기") · "표시 이름 · 아이콘" · "알림 일시 중지" · "환경설정".
- 테마는 설정 → "화면 — 테마" 에서 다크(기본) · 라이트.

## 5. PC 연결하기 (페어링)

처음 한 번만 한다. 초대를 **만드는 쪽**과 **받는 쪽**이 있다.

설정 → 연결의 **"페어링"** 카드 — "한쪽이 초대를 만들어 보내고, 받은 쪽이 붙여 넣으면 연결됩니다." 아래 같은 모양 큰 단추 둘 — **"초대 생성"**(＋) · **"초대 수락"**(→ — 누르면 붙여 넣기 칸이 펼쳐지고, 다시 누르면 접힌다).

1. 만드는 쪽(예: `user-b`): "+ 새로 만들기" → **"초대 생성"**(또는 설정 → 연결) → 페어링 카드 "초대 생성" → **"초대 복사"**.
   복사한 초대 메시지를 메신저 등으로 상대에게 보낸다. 초대는 **5분 안에 한 번**만 쓸 수 있다.
2. 받는 쪽: 레일 "+"(또는 "+ 새로 만들기" → **"초대 수락"** · 페어링 카드 "초대 수락") → 펼쳐진 칸에 받은 초대 메시지를 통째로 붙여 넣기 → **"추가 · 승인"**.
   레일 "+" 는 페어링 카드를 맨 위로 올리고 칸에 바로 초점을 둔다.
3. 양쪽 "연결 목록" 에 상대가 "페어링됨" 으로 보인다. 초대를 만든 쪽은 따로 승인하지 않아도 자동 등록되고 "새 연결 등록" 알림이 온다.

- **지문 확인**: 처음 잇는 상대라면 상대 화면의 "프로필 → 사용자 정보 → 지문" 과 내 연결 목록의 지문이 같은지 전화 · 대면으로 확인한다.
- 모르는 연결이 등록됐으면 연결 목록에서 바로 **"삭제"** 한다.
- 연결 목록 줄 = ⋮⋮(끌기) · 상대 타일 · 이름 · 부제(이름 · PC · 접속 상태) · "그룹 ▾" · **"관리"**. "관리" 를 누르면 상세(지문 · 주소 · 모델 · effort ·
  "저장" · "승인" 또는 "다시 알리기" · "연결 확인" · "내 에이전트 편집" · "삭제")가 펼쳐지고, 다시 누르면 접힌다.
- "관리" 상세에서 그 상대 요청에 쓸 모델 · effort 를 이 PC 에서만 바꿀 수 있다. 타일 표시 이름 · 아이콘은 사이드바 ✎ 또는 타일 메뉴(4.2).

**연결 목록 — 그룹 절**: 연결 목록은 레일 그룹(4.1)마다 절이 있고(레일 순서, 한 상대는 넣은 그룹마다 보인다) 끝에 "그룹에 없는 연결" 절이 있다.
위 검색 칸(이름 · PC · 지문)으로 거른다.

- **옮기기** — 줄을 끌어 다른 절에 놓으면 놓은 그룹에 넣고 원래 절의 그룹에서 뺀다. "그룹에 없는 연결" 에 놓으면 빼기만 한다.
- **그룹 ▾** — 줄의 "그룹 ▾" → 그룹마다 체크(끌기 없이 넣고 빼기) · "+ 새 그룹에 넣기…".
- **+ 그룹 추가** · 절 머리(그룹 타일 · 이름 · 수) **연필**(이름 바꾸기) · **휴지통**(삭제 — 한 번 더 묻고 그룹만 지운다, 대화 · 연결은 남는다).
- 바꾼 그룹은 레일 그룹 타일에 바로 반영된다.

## 6. 내 에이전트 등록 (답하는 쪽)

설정 → 내 에이전트 → 머리의 **"에이전트 등록"**(또는 "+ 새로 만들기" → "에이전트 등록") — 등록 칸이 보이고, 다시 누르면 숨는다.

| 칸 | 내용 |
|---|---|
| 이름 | 1 ~ 64자. 상대가 이 이름으로 부른다 — **등록 뒤 바꿀 수 없다**(바꾸려면 새로 등록) |
| 폴더(절대 경로) | 에이전트가 읽을 수 있는 범위이자 답의 맥락. 예 `D:\work\shop-api` |
| 추가 지시 | 답하는 방식. "추가 지시" 옆 **'?'** 의 사용 예 참고 — 예: 결론 먼저 세 줄, 근거 파일 경로 함께 |

- **도구는 고르지 않는다** — 모든 에이전트가 탐색 도구(읽기 전용) `Read` · `Grep` · `Glob` · `LS` · `NotebookRead` 를 항상 쓴다(질의를
  처리하려면 이 도구가 다 있어야 한다). 화면에는 "탐색 도구(읽기 전용) 항상 사용" 안내만 있다.
- 내 에이전트 목록은 묶지 않은 한 목록이다(검색 칸 없음). 줄 = 타일 · 이름 · 폴더 · **"관리"**(상세 — 이름 · 폴더 · 도구 ·
  추가 지시 · "저장" · "삭제"). 에이전트 화면의 ✎ 로 오면 그 에이전트 상세가 펼쳐진 채 보인다.
- 등록한 뒤 폴더 · 추가 지시를 고칠 수 있다. **폴더를 바꾸면** 그 에이전트가 이어 가던 모든 대화의 맥락이 처음부터 다시
  시작된다. 지우고 같은 이름으로 다시 등록해도 같다.
- 에이전트는 항상 "문의 응답 전용" 규칙으로 실행된다 — 파일 생성 · 수정 · 삭제, 명령 실행, 설정 변경 요청에는 하지 않고 이유를 답한다.
- ⚠ 그래도 **폴더 안에서 읽을 수 있는 내용은 답에 실려 상대에게 갈 수 있고, 답을 만드는 동안 Claude 모델 서비스로도 간다.** 비밀(키 ·
  토큰 · 개인정보)이 든 폴더는 등록하지 않는다.
- 앱 데이터 폴더(`%LOCALAPPDATA%\coworkAgent`)를 품는 폴더(예: 사용자 폴더 전체 · `C:\`)와 네트워크 경로(`\\서버\…`)는 등록할 수 없다.
  예전에 그렇게 등록한 에이전트는 실행하지 않고 상대에게 "에이전트 폴더를 쓸 수 없다" 로 답한다 — 폴더를 바꾼다.

## 7. 대화하기

### 7.1 새 대화

"+ 새로 만들기" → **"새 대화"**(또는 사이드바 대화방 목록 머리의 + — "나" 에서는 상대별 절마다 하나, "에이전트" 화면에서 상대 에이전트 누르기).

| 칸 | 내용 |
|---|---|
| 상대 · 상대 에이전트 | 연결한 PC 와 그 PC 에 등록된 에이전트 |
| 내 에이전트로 자동 왕복 | 보통은 "안 함 — 상대 에이전트에게만"(자동 왕복은 10장) |
| 제목 | 비우면 첫 메시지 앞부분 — 이 PC 에만 보인다 |
| 메시지 · 글 종류 | 질문 본문과 "질의"(기본) · "요청" → "보내기" |

### 7.2 보내기 · 답 받기

- 대화는 메신저처럼 말풍선으로 이어진다 — **이 PC 쪽 글**(내가 쓴 글 · 상대 요청에 내 에이전트가 한 답)은 오른쪽, **상대 사람 · 상대 에이전트 글**은
  왼쪽에 아바타 · 이름 · 시각과 함께. 색으로도 가른다 — 내 글은 강조색(진한 파랑) 바탕, 상대 글은 그 상대 타일 색을 연하게 깐 바탕 + 왼쪽 띠. 날짜가 바뀌면 구분선("오늘" · "어제" · "10.14" 처럼 월.일)이 들어간다. 말풍선은 대화 칸 폭의 90% 까지 넓어진다.
  머리글 "원문 보기" 를 누르면 모든 글이 markdown 원문으로, "대화 보기" 로 돌아온다.
- 입력창: **Enter = 보내기**, Shift+Enter = 줄바꿈(한글 조합 중 Enter 는 보내지 않는다). 서식 버튼(굵게 · 목록 · 코드)과 markdown 을 쓸 수 있다.
  한 글은 16 KiB 까지.
- 보낸 글은 상대 PC 의 대기열에 들어가 차례대로 실행된다. 실행은 한 번에 최대 30분.
- **상대가 꺼져 있어도 보낸다** — 상대에 닿지 않으면 글을 이 PC 에 보관하고 내 글 아래에 **"보내는 중"** · **"보내는 중 — 상대에 닿지 않아
  다시 보냄(n회)"** 이 보인다. 상대가 켜지면(이 PC 를 다시 켠 경우 포함) 사람이 다시 보내지 않아도 전달 · 실행 · 답이 온다. 같은 글은 몇 번 다시
  가도 상대에서 한 번만 실행된다. 답도 같다 — 답할 때 묻는 쪽이 꺼져 있었어도 켜지면 답이 도착한다.
- 상대에 오래(앱이 켜져 있던 시간으로 24시간) 닿지 않으면 보내기를 멈추고 글이 실패로 바뀐다 — **"보내지 못함 — 상대에 오래 닿지
  않았다(입력창에서 다시 보낼 수 있다)"**. 입력창에 다시 써서 보낸다.
- 상대 PC 가 이미 다른 요청을 실행 중이면(동시 실행 상한) 거절하지 않고 기다린다 — 내 글 아래에 **"상대 PC 에 처리 중인 작업이 많아 응답을
  기다립니다(앞에 k건)"**, 실행이 시작되면 **"처리 중"** 이 보인다.
- 실행이 길어지면 상대 에이전트가 하는 일이 단계로 보인다 — 예 **"처리 중 — 2턴 · Read 3 · Grep 1 · 41초"**(턴 수 · 쓴 도구 이름별 횟수 ·
  걸린 초, 10초에 한 번 이하로 바뀐다). 도구에 준 입력 · 파일 경로 · 에이전트가 쓴 글은 오지 않는다. 대기 · 처리 중 표시는 이 PC 의 앱을 다시
  켜면 다음 알림까지 사라진다.
- 진행은 실행 상세 **'진행'**(요청 보냄 · 대기열 · 실행 완료 · 응답 받음)에서 본다. 답에는 실행한 모델 · effort · 턴 · 시간이 함께 남는다.
- 화면은 5초마다 새로 고친다.

### 7.3 글 종류 — 질의 · 요청

- 입력창의 **"질의"**(기본) · **"요청"** 중 고른다. 보낸 뒤에는 "질의" 로 돌아간다.
- **질의** = 상대 에이전트가 읽기 전용으로 답한다(위 7.2).
- **요청** = 고치기 · 만들기처럼 상대 사람이 해야 하는 일. 에이전트를 **실행하지 않고** 상대 PC 의 **요청 목록**에 "대기" 로 올라간다(입력창
  안내 "실행 없이 상대 요청 목록에 등록 — 상대가 수용 · 반려합니다"). 답은 오지 않고, 상대가 바꾼 상태 · 메모가 돌아온다(9장).
  상대가 집중 중이어도 요청은 받는다. 요청에는 @멘션을 쓰지 않는다.
- 요청 모아 보기: 사이드바 **'요청'**(9장) · 실행 상세 **'요청'**(그 대화). 요청 글 말풍선에는 "요청 · 대기" 같은 표시가 붙는다.

### 7.4 이어 쓰기와 맥락

- 같은 대화에 이어 쓰면 에이전트가 **앞 대화를 기억한 채** 답한다. 상대 쪽 사람이 그 사이 같은 대화에 쓴 글도 맥락으로 함께 넘어간다.
- 맥락 없이 새로 묻고 싶으면 **새 대화**를 연다.
- 답하는 PC 에서 Claude 의 그 대화 기록(세션)이 지워졌으면 그 질문은 **새 세션으로 한 번 다시 실행해** 답한다 — 앞 대화 기억은 없고, 그 뒤로는
  새 세션을 잇는다(예전에는 그 대화의 질문이 계속 실패했다).
- 오래 쉰 대화(약 30일 넘게 — 상대 PC 의 Claude Code 기록 정리 설정에 따름)는 이어 쓰기가 실패할 수 있다 — 새 대화로 묻는다(15장).

### 7.5 메시지 작업 · 정리

- 말풍선 우상단 아이콘 두 개:
  - **북마크** — 누르면 그 글을 '북마크 항목' 에 넣고, 다시 누르면 뺀다("북마크 해제"). 북마크한 글은 노란 아이콘이 늘 보이고, 그 밖은 마우스를
    올리거나 Tab 으로 닿을 때 보인다.
  - **복사** — 늘 보인다. 누르면 본문 markdown 원문이 클립보드에 들어가고 "복사했다" 가 잠깐 보인다.
- 말풍선 아래 작은 단추: 받은 요청이면 상태에 따라 **"수용"** · **"반려"** · **"완료"**(9장) · 알리지 못한 상태는 **"다시 알리기"**. "다시 보내기" 단추는
  없다 — 같은 글을 다시 보내려면 입력창에 다시 쓴다. 편집 · 삭제는 편집 모드(7.6).
- 대화 머리글 **"북마크 n"** = 이 대화에서 북마크한 글 수 — 누르면 세부정보 패널의 북마크 항목이 열린다.
- ☆ → ★ : 그 대화를 즐겨찾기에(대화방 줄 · 대화 머리글 ☆ — 사이드바 '즐겨찾기' 메뉴에 모인다). 북마크한 글은 '북마크 항목' 에 모인다 — ★ 는
  **대화 하나**(자주 들어가는 대화), 북마크는 **글 하나**(긴 대화 속 쓸 만한 답).
- **내 활동**(상단 바 종 · "나" 사이드바): 상대 쪽 글 · 자동 왕복 시작 · 끝 · 실패 · 상대 반영 실패(7.6)가 상대별 절 안에 최신순, 안 본 수 배지. 종류 ·
  본문 검색으로 거른다.
- 안 읽은 답이 있으면 대화 행이 굵게, 레일 타일에 배지. 대화를 열면 지워진다.
- 제목 · ★ · 북마크 · 읽음 · 내 활동 본 표시 · 타일 표시 이름 · 그룹 · 절 접힘은 **이 PC 에만** 남는다(상대에게 보내지 않는다).

### 7.6 편집 모드 — 내 글 지우기 · 고치기

이미 끝난 대화를 정리하는 기능이다. **에이전트는 다시 실행하지 않는다.**

- 입력창 위 오른쪽 **"편집"** 을 누르면 편집 모드 — 입력창 자리에 **"n개 선택 · 삭제 · 완료"** 막대가 뜬다(그동안 보내기 없음). 지금 열린
  대화에만 적용되고, 다른 대화로 가거나 **"완료"** 를 누르면 끝난다.
- 고를 수 있는 글 = **내가 쓴 사람 글**(웹 화면 · CLI) 중 **끝난 글**(답이 왔거나 · 실패했거나 · 실행 없는 글). 에이전트 답 · 상대가 쓴 글 ·
  보내는 중 · 실행 대기 · 실행 중인 글에는 체크박스가 없다.
- **삭제** — 체크박스로 여러 글을 고르고 "삭제". 흔적 없이 지워진다(북마크 항목 · 검색 · 주고받은 글 · 요청 목록 · 내 활동에서도). 요청을 지워도
  그 답은 남는다.
- **편집** — 글의 연필 아이콘 → 말풍선 안 입력칸에서 고치고 "저장"(한 번에 하나). 고친 글에는 **"(편집됨)"** 이 붙는다. 순서 · 요청 상태는 그대로다.
- 삭제 · 저장을 누르면 **어디에 반영할지** 묻는다:
  - **"내 창에서만"** — 이 PC 기록만 바뀐다. 상대 화면은 그대로.
  - **"상대 창에도"** — 상대 PC 의 같은 글도 지워지거나 같은 본문 + "(편집됨)" 이 된다(상대 요청 목록 포함). 상대가 꺼져 있으면 이 PC 가
    보관했다가 켜지면 보낸다. 24시간 안에 못 보내거나 상대가 받지 못하면 내 활동에 **"상대 반영 실패 — …"** 가 뜬다(이 PC 에는 이미 반영됐다).
- 알아 둘 점: 이미 돈 실행의 맥락(Claude 세션)은 에이전트가 기억한다 — 고치거나 지워도 에이전트 기억은 바뀌지 않는다. 같은 대화에 이어
  쓰면 **다음** 실행에는 고친 · 지운 상태의 실행 없는 글이 맥락으로 간다.

## 8. 같은 대화에서 다른 에이전트 부르기 — @멘션

- 내가 연 대화(자동 왕복 아님)의 입력창에서 `@` 를 치면 상대 PC 의 에이전트 후보가 뜬다(입력창 힌트 "@ 로 상대 에이전트 부르기").
  ↑ ↓ 로 고르고 Enter · Tab 으로 넣는다. Esc 로 닫는다.
- 예: `guide` 와의 대화에서 "@review 이 변경의 위험을 봐 주세요" → 상대 PC 의 `review` 가 답한다. 답에는 실행한 에이전트 이름이 붙는다.
- 부른 에이전트는 이 대화 안에서 **자기 맥락을 따로** 이어 간다. 멘션 없이 쓰면 원래 대화 에이전트가 자기 맥락으로 답한다.
- 상대 목록에 없는 `@이름`(오타 등)은 한 번 막고 알려 준다 — 멘션이 아니라면 같은 글을 한 번 더 보내면 멘션 없이 간다.
- 받은 대화 · 자동 왕복 대화에는 멘션이 없다.

## 9. 요청 목록 — 수용 · 반려 · 완료

- 사이드바 **'요청'** — 받은 요청 중 "대기" 수가 배지로 보인다. 화면 위 탭 **"받은 요청"** · **"보낸 요청"**, "상태" 로 거른다(전체 · 대기 ·
  수용 · 반려 · 완료). 행 = 상대 · 상태 · 시각 · 대화 · 본문 앞부분 · 메모, 누르면 그 대화의 그 글로.
- 상태는 **받은 쪽**(요청을 받은 PC)만 바꾼다: **대기 → 수용 · 반려**, **수용 → 완료**. 단추를 누르면 메모 한 줄 칸(선택, 200자까지)이
  열리고 확인하면 바뀐다. 끝난 요청(반려 · 완료)은 되돌리지 않는다.
- 바뀐 상태 · 메모는 요청자 화면의 그 글 태그("요청 · 수용" 등) · 메모 · '보낸 요청' 목록에 보이고, 요청자에게 알림("요청 상태 — …")이
  간다. 요청자 앱이 꺼져 있어도 이 PC 에 보관했다가 켜지면 바뀐 순서대로 보낸다. 요청자가 거절했을 때만 경고("이 PC 에는 바꿨다 — 상대에
  알리지 못했다 …")가 뜬다. 요청자에 오래(24시간) 닿지 않거나 요청자가 받지 않으면 그 요청에 **"요청자에게 상태를 알리지 못함"** 이 보이고
  **"다시 알리기"** 로 같은 상태 · 메모를 다시 보낸다.
- 요청은 실시간으로 처리하지 않는다 — 목록에서 모아 보고 처리한 뒤 상태로 답한다.

## 10. 자동 왕복 대화 — 내 에이전트 ⇄ 상대 에이전트

- "+ 새로 만들기" → **"새 대화"** → 아래 "내 에이전트로 자동 왕복" 에서 내 에이전트, "자동 왕복 상한"(1 ~ 50, 기본 10) → 첫 글 "보내기".
- 상대 에이전트의 답 → 내 에이전트 → 상대 에이전트 … 를 상한까지 자동으로 주고받는다.
- 멈춤: 어느 쪽이든 사람이 그 대화에 글을 쓰거나 **"멈춤"**. 대화를 연 쪽은 **"재개"** 로 다시 시작한다(횟수는 0부터).
- 저절로 멈추는 때: 상한 도달 · 실행 실패 · 상대 거절 · 집중 · 상대에 24시간 닿지 않음. 내 활동에 끝 사유가 남는다. 넘기는 중 상대가 잠깐 꺼진
  것은 멈추지 않는다 — 보관했다가 켜지면 이어 간다.
- 상한 기본값은 설정 → 알림 "대화 턴에 대한 상한 기본값". 내 에이전트 실행은 **내 PC** 의 Claude 사용량을 쓴다.

## 11. 집중 · 접속 상태

- 프로필 메뉴(우상단)에서 **"받기 가능"** · **"집중"** 중 하나를 고른다. 내 상태는 프로필 아이콘 테두리 · 점 색으로 보인다 — 초록 받기 가능 ·
  주황 집중 · 붉은 **앱과 연결 끊김**(이 화면의 요청이 이 PC 의 앱에 연달아 두 번 닿지 못하면 저절로 표시되고, 다시 닿으면 원래 색으로 돌아온다).
  집중 동안 상대의 새 요청은 받는 순간 거절된다 — 이 PC 에는 기록 · 실행 · 알림이 없고, 상대 화면에는 "상대가 집중 중".
- 진행 중인 자동 왕복은 다음 차례에서 멈추고, 집중 동안 알림도 멈춘다. 앱을 다시 켜도 집중은 유지된다.
- 상대가 집중이라 실패한 글은 상대가 집중을 끈 뒤 입력창에서 다시 보낸다.
- **접속 상태 = 마지막 통신**: 레일 타일의 점 · 이름 끝 · 사이드바 머리 · 대화 머리글에 **"방금 통신"**(75초 안) · **"n분 전 통신"** · **"n시간
  전 통신"** · **"n일 전 통신"** · **"통신 기록 없음"**. 상대가 집중 중이면 **"집중 중 · 방금 통신"**. 점은 방금 통신했을 때만 켜진다.
- 따로 주기적으로 확인하지 않는다 — 글 · 답을 주고받을 때, 앱을 켤 때, 웹UI 를 열 때, 레일에서 상대 타일을 고를 때(1분 안에 통신했으면
  다시 묻지 않음) 바뀐다. 그래서 켜져 있는 상대도 오래 주고받지 않았으면 "n분 전 통신" 이다. 상대가 꺼져 있어도 보낸 글은 보관됐다가
  닿으므로(7.2) 표시와 상관없이 보낼 수 있다.

## 12. 알림

- 설정 → 알림 → **"인바운드 요청 알림(브라우저 알림 · 트레이 표시)"** 을 켠다(기본 꺼짐) → 브라우저의 알림 권한 묻기에 허용.
- 종류별로 켜고 끈다: "페어링 요청 · 승인 · 새 연결 등록" · "받은 요청(상대 사람 글)" · "받은 답" · "자동 왕복"("시작 · 끝만" ·
  "글마다" · "알리지 않음") · "알림에 글 앞부분 보이기".
- 브라우저 알림은 **웹UI 탭이 열려 있을 때만** 뜬다. 트레이 주황 점은 탭과 무관하다.
- Windows 방해 금지(집중 지원) 중에는 배너를 OS 가 막는다(알림 센터에는 남는다).
- 잠깐 끄기: 프로필 → **"알림 일시 중지"**(이 PC 에만 — 켜 둔 동안 온 알림은 버린다).

## 13. 실행 설정 (답하는 쪽)

- 설정 → **"실행 — 모델 · effort"**: 받은 질의를 실행할 때의 기본값(처음 `sonnet` · `high`). 모델은 드롭다운에서 `opus` · `sonnet` ·
  `haiku` 중 고른다.
- 상대별로 다르게 하려면 연결 목록에서 그 상대를 펼쳐 덮어쓴다(드롭다운 첫 항목 "기본값(…)" = 전역 기본값).
- **동시 실행 상한**(1 ~ 8, 처음 2): 이 PC 에서 한꺼번에 도는 실행 수. 넘는 요청은 거절하지 않고 닿은 순서로 기다린다(같은 대화는 늘 한 번에 하나).
  지금 실행 중 · 대기 목록은 대화 화면 실행 상세 맨 위 **"이 PC 실행"** — 항목을 누르면 그 대화.

## 14. AI 에이전트용 CLI

앱이 떠 있는 PC 에서 내 AI 에이전트(또는 사람)가 명령줄로 묻고 이력을 본다. 앱 화면과 같은 권한으로 동작하고, CLI 로 쓴 글은 양쪽
이력에 "AI 에이전트(CLI)" 로 표시된다.

```powershell
coworkAgent peers                                             # 연결한 상대
coworkAgent ask user-b "이 저장소의 빌드 명령은?" --agent review  # 새 대화로 묻고 답을 기다린다
coworkAgent ask user-b "둘째 항목의 근거 파일은?" --conv 12      # 대화 12 에 이어 묻기
coworkAgent ask user-b "위험한 변경이 있나?" --conv 12 --agent guide  # 대화 에이전트가 아니면 멘션
coworkAgent ask user-b "빌드 명령은?" --agent review --id build-q1   # 같은 --id 로 다시 실행해도 새로 보내지 않는다
coworkAgent wait 7                                             # 트랜잭션 7 의 답을 이어서 기다린다
coworkAgent status 7                                           # 트랜잭션 7 의 지금 상태 한 번
coworkAgent history user-b --conv 12                           # 대화 이력
```

- `<상대>` = `coworkAgent peers` 가 보여 주는 상대의 **원래 이름**(대소문자 무시) 또는 지문 앞 4자 이상. 화면의 표시 이름(별칭)으로는 찾지
  못한다(사용법 오류 2). 옵션 `--json` · `--no-wait`(답을 기다리지 않음) · `--id <키>`(아래).
- **`ask` 하나 = 앱의 트랜잭션 하나**. 앱이 질문의 상태를 지키고 CLI 는 그것을 본다.
  - `--id <키>`(1 ~ 64자 영문 · 숫자 · `.` `_` `-`, 이 PC 안에서 고유) — 같은 키로 다시 실행하면 새로 보내지 않고 그 트랜잭션의 결과를 받는다.
    AI 에이전트가 재시도해도 상대에서 두 번 실행되지 않는다.
  - `wait <트랜잭션>` — CLI 가 중간에 끊겼거나 종료 코드 7 로 끝난 뒤 답을 이어서 기다린다. `status <트랜잭션>` — 지금 상태를 한 번 출력
    (`보내는 중` 단계면 `sending`, 그 밖 `sent` · `queued` · `running` · `answered` · `failed` · `stalled`).
  - 트랜잭션 번호는 `--json` 결과의 `tx`, 그리고 종료 코드 6 · 7 의 안내 문구(`coworkAgent wait <번호>`)에 있다.
- 기다리는 동안 상태가 바뀔 때마다 표준 오류에 한 줄 — "보내는 중 — 상대에 아직 닿지 않아 이 PC 에 보관했다(다시 보냄 n회)" · "대기 중 — 상대
  PC 에 처리 중인 작업이 많다(앞에 k건)" · "처리 중 — 2턴 · Read 3 · Grep 1 · 41초"(`--json` 이면 `{"progress":"sending"|"queued"|"running", …}`
  줄).
- 상대가 대기 · 실행 중으로 확인되는 동안은 계속 기다린다. 상대에 **10분 동안 닿지 않으면** 종료 코드 7 로 끝난다 — 질문은 앱에 남아 있으니
  나중에 `wait <트랜잭션>` 으로 이어 받는다. CLI 자체 대기 상한은 24시간이다.
- 종료 코드: 0 성공 · 2 사용법 오류 · 3 앱이 실행 중이 아님 · 4 API 거부 또는 전달 여부 불명(**다시 보내지 말고** `history` 로 확인) ·
  5 답이 실패 · 질문을 상대에 보내지 못함 · 6 시간 초과(24시간) · 7 상대에 닿지 않아 멈춤(`wait` 로 이어 받기).

- 위치: `%LOCALAPPDATA%\coworkAgent\` — 대화 DB(`coworkAgent.db`) · 신원 키(`identity.key`) · 로그(`logs\`) · 업데이트 전 사본
  (`coworkAgent.db.v{N}.bak`).
- **백업**: 앱을 끄고 폴더째 복사한다. 신원 키를 잃으면 모든 상대와 다시 연결해야 한다.
- **다른 PC 로 복사하지 않는다** — 같은 신원이 두 PC 에 생긴다.
- 로그인 자동 실행 등록은 데이터 폴더 밖(Windows `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 의 `coworkAgent` · macOS
  `~/Library/LaunchAgents/com.coworkagent.plist`)에 있다 — 앱을 지울 때는 설정에서 먼저 끈다.
- **초기화**: 앱을 끄고 폴더를 지운다(연결 · 에이전트 · 대화 · 신원이 모두 사라진다). 상대 PC 의 이력은 그대로 남는다. 에이전트가 답한
  대화의 맥락은 Claude Code 기록(기본 `%USERPROFILE%\.claude\projects\…` — 환경 변수 `CLAUDE_CONFIG_DIR` 을 쓰면 그 아래)에 따로
  남으니 함께 지운다.
- 새 버전은 DB 를 올리기 전에 `.v{N}.bak` 사본을 남긴다. 옛 버전으로 돌아가려면 앱을 끄고 그 사본을 `coworkAgent.db` 로 바꿔 쓴다
  (옛 버전은 새 DB 를 열지 않는다).
- ⚠ 사본으로 바꾸면 **사본을 만든 뒤에 생긴 대화 · 연결 · 설정은 사라진다.** 바꾸기 전에 지금의 `coworkAgent.db` 를 다른 이름으로 복사해
  둔다. 같은 버전의 사본은 **처음 한 번만** 만들어진다 — 되돌린 뒤 다시 새 버전을 실행해도 그 사본은 새로 떠지지 않고 옛 시점 그대로다.

## 16. 문제 해결

| 증상 | 원인 · 할 일 |
|---|---|
| 실행해도 창이 안 뜬다 | 정상 — 트레이 아이콘 "열기" |
| 작업 관리자에 coworkAgent 가 둘 | 정상 — 하나는 앱, 하나는 앱이 비정상 종료되면 다시 띄우는 감시 프로세스(트레이 "종료" 면 둘 다 끝난다) |
| 로그인해도 앱이 켜지지 않는다 | 설정 → 시작 — 자동 실행이 꺼져 있다 · 실행 파일을 옮긴 뒤 한 번도 실행하지 않았다(실행하면 새 경로로 고친다) |
| 붉은 트레이 아이콘 "앱이 60초 안에 3번 비정상 종료" | 로그(`logs\coworkAgent.log`)의 "패닉: …" 줄 · 직전 오류를 확인하고 다시 실행 |
| 새 버전을 실행했는데 화면이 그대로다 | 옛 버전이 아직 떠 있다 — 트레이 "종료" 뒤 새 버전 실행 |
| 붉은 트레이 아이콘 | 시작 실패 — "오류 보기" 의 사유(옛 앱(agentNetwork)이 켜져 있음 · 데이터 폴더 권한 · "DB 스키마 N 가 이 실행 파일(M)보다 새롭다" 등) |
| 초대 수락이 실패한다 | 5분 지남 · 이미 쓴 초대 · 방화벽 · 다른 네트워크 — 상대에게 새 초대를 받는다 |
| 답이 "실행 실패: 받는 PC 의 Claude Code 버전이 낮다" | 답하는 PC 에서 `claude update` |
| 답이 "실행 실패: 받는 PC 의 시간 제한(30분)을 넘겼다" | 30분 상한 — 질문 범위를 좁힌다 |
| 답이 "실행 실패: 받는 PC 에서 실행하지 못했다 — 원인은 받는 PC 화면에 있다" | 원인(오류 원문)은 답하는 PC 의 같은 대화에만 있다 — 상대에게 확인을 부탁한다 |
| 답이 "실행 실패: 받는 PC 의 에이전트 폴더를 쓸 수 없다 …" | 답하는 PC 에서 그 에이전트 폴더를 앱 데이터 폴더를 품지 않는 곳으로 바꾼다 |
| "연결이 끊겼습니다 — 트레이 아이콘 메뉴 '열기' 로 다시 여세요" | 트레이 "열기" — 새 탭 · 다시 켠 앱에는 열쇠가 없다 |
| "상대가 집중 중" | 상대가 집중을 끈 뒤 입력창에서 다시 보낸다 |
| 내 글 아래 "보내는 중 — 상대에 닿지 않아 다시 보냄(n회)" | 상대 앱이 꺼져 있거나 네트워크가 끊겼다 — 그대로 두면 상대가 켜질 때 보낸다(다시 보낼 필요 없다) |
| 내 활동 "상대 반영 실패 — 편집 — …" · "상대 반영 실패 — 삭제" | 편집 · 삭제를 상대 창에 반영하지 못했다 — 상대가 24시간 꺼져 있었거나 상대 쪽에 그 글이 없다(상대가 먼저 지움). 이 PC 에는 반영됐다 — 필요하면 상대에게 알린다 |
| "보내지 못함 — 상대에 오래 닿지 않았다(입력창에서 다시 보낼 수 있다)" | 24시간 동안 상대에 닿지 않아 포기했다 — 상대 앱 · 네트워크를 확인하고 입력창에서 다시 보낸다 |
| CLI 종료 코드 7 "상대에 닿지 않아 멈췄다 — 트랜잭션 n 는 남는다 …" | 상대에 10분 닿지 않았다 — 상대가 켜진 뒤 `coworkAgent wait n` 으로 이어 받는다(같은 `ask` 를 `--id` 없이 다시 실행하면 새 질문이 된다) |
| "실행 도중 상대 앱이 종료돼 결과가 없다 — 다시 보내 주세요" | 실행 중 상대 앱이 꺼졌다 — 입력창에서 다시 보낸다 |
| 상대 화면에는 답이 있는데 내 쪽에 안 온다 | 답을 보낼 때 이 PC 가 꺼져 있었다 — 상대 PC 가 보관했다가 다시 보낸다(이 PC 를 켜면 곧 온다). 상대 쪽에 "답 미전달" 이 보이면 24시간 닿지 않아 포기한 것 — 상대에게 받아 보거나 입력창에서 다시 보낸다(다시 실행된다) |
| 같은 대화에서 매번 "실행 실패" (No conversation found …) | 상대 PC 의 Claude Code 대화 기록이 정리 · 삭제됐다 — **새 대화**로 묻는다(알려진 제한) |
| 상대가 "n분 전 통신" · "통신 기록 없음" | 주기 확인이 없어 오래 주고받지 않으면 그렇게 보인다(11장) — 레일에서 그 타일을 고르면 다시 확인한다. 계속이면 상대 앱 꺼짐 · 네트워크 · 방화벽 |
| 프로필 → 사용자 정보 "피어 포트 …(임의 — 47100 사용 중: 이름, PID n)" · 트레이 툴팁에 같은 내용 | 다른 프로그램이 47100 을 잡았다 — 그 프로그램을 끄고 앱을 다시 켜면 47100 으로 받는다. 임의 포트여도 페어링된 상대는 이 PC 가 시작할 때 보내는 알림으로 새 주소를 따라온다 |
| 브라우저 알림이 안 온다 | 알림 설정 꺼짐 · 브라우저 권한 차단 · 웹UI 탭 닫힘 · Windows 방해 금지 · "알림 일시 중지" · 집중 |

## 17. 알아 둘 점

- 상대의 요청은 **내 Claude 구독 사용량**을 쓴다. 상한은 실행 1번당 30분뿐이다.
- 내 에이전트 폴더에서 읽을 수 있는 내용은 답으로 상대에게 나갈 수 있다.
- 초대 메시지가 새면 그 5분 안에 다른 PC 가 등록될 수 있다 — 모르는 연결은 바로 삭제한다.
- 사내망 전용 도구다. 앱은 상대 주소가 사내망인지 검사하지 않으므로 수신 포트를 인터넷에 열지 않는다.
- **방화벽 프로필** — 앱은 방화벽 규칙을 만들지 않는다. 처음 실행할 때 Windows 허용 창에서 "공용 네트워크" 까지 허용했으면 카페 · 공용 Wi-Fi 에서도
  그 망의 다른 기기가 수신 포트(47100)에 닿는다(연결은 페어링한 상대만 된다 — [보안 검토](../../overview/security-review.md) 7장). 확인 · 공용(Public)
  끄기(관리자 PowerShell — 끄는 명령의 효과는 이 문서 작성 PC 에서 확인하지 않았다, 확인 필요):

  ```powershell
  # 앱 규칙의 프로필 — Profile 에 Public 이 있으면 공용망에서도 허용
  Get-NetFirewallApplicationFilter | Where-Object Program -like '*coworkAgent*' | Get-NetFirewallRule | Select-Object DisplayName, Direction, Action, Profile
  # 공용 끄기 — 도메인 · 개인 망만 허용
  Get-NetFirewallApplicationFilter | Where-Object Program -like '*coworkAgent*' | Get-NetFirewallRule | Set-NetFirewallRule -Profile Domain, Private
  ```
- 전달된 대화 이력은 두 PC 에 모두 남고, 메시지 수정 · 삭제는 없다.
- 답을 만들 때 질문과 에이전트가 읽은 파일 내용이 Claude 모델 서비스(사내망 밖)로 나간다.
